*&---------------------------------------------------------------------*
*&      Form  CHECK_BUKRS_AUTHORITY
*&---------------------------------------------------------------------*
* Company-code authorization gate, via the standard FI object
* F_BKPF_BUK (the same one real posting/reversal transactions check),
* ACTVT 03 (Display) - the minimum needed to work with this company's
* data in this program at all (search, view, approve, post, reverse).
* Without this, any user able to run the program could act on ANY
* company code typed into P_BUKRS, regardless of their real FI
* authorization. Called from every entry point that validates P_BUKRS
* (both main programs' selection screens and their START-OF-SELECTION
* background safety net), right next to the existing "Enter a Company
* Code" check.
*---------------------------------------------------------------------*
FORM check_bukrs_authority USING pu_bukrs TYPE bukrs.

  AUTHORITY-CHECK OBJECT 'F_BKPF_BUK'
    ID 'BUKRS' FIELD pu_bukrs
    ID 'ACTVT' FIELD '03'.
  IF sy-subrc <> 0.
    MESSAGE |No FI authorization for company code { pu_bukrs }| TYPE 'E'.
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  CHECK_SEARCH_FILTERS
*&---------------------------------------------------------------------*
* "Search New Candidates" (P_MNEW) reads EDOCUMENT/EDOBRINCOMING -
* company-wide tables with no built-in scoping of their own (see
* SELECT_CANDIDATE_DOCUMENTS) - P_BUKRS alone does not limit that read
* at all. Left completely open (every one of these select-options
* empty), a search would walk the company's entire eDocument history
* in one go, both slow and - per the earlier fix - still capable of
* writing a Y0033FI_ICM_EDOC row for every LINK_ERROR found along the
* way. Require at least one other filter to narrow it down first.
* "View My Candidates" is not checked here - it only ever reads our
* own already-bounded Y0033FI_ICM_ITEM data, not the company-wide
* eDocument tables.
*
* Every filter below bounds BOTH search models: S_DATUM/S_ACCKEY are
* eDocument filters, and when either is filled the stock-transfer
* model (which has no eDocument) returns nothing - see
* SELECT_TRANSFER_CANDIDATES.
*---------------------------------------------------------------------*
FORM check_search_filters.

  DATA lv_ok TYPE abap_bool.
  PERFORM has_search_filters CHANGING lv_ok.
  IF lv_ok = abap_false.
    MESSAGE 'Fill in at least one filter besides Company Code' TYPE 'E'.
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  HAS_SEARCH_FILTERS
*&---------------------------------------------------------------------*
* Same rule as CHECK_SEARCH_FILTERS, without raising the message - for
* callers that must not stop the run (AUTO_APPROVE_CANDIDATES in a
* background job, see Y0033FI_ICMS_F02).
*---------------------------------------------------------------------*
FORM has_search_filters CHANGING pc_ok TYPE abap_bool.

  pc_ok = xsdbool( s_datum[]  IS NOT INITIAL OR s_nfenum[] IS NOT INITIAL
                OR s_docnum[] IS NOT INITIAL OR s_series[] IS NOT INITIAL
                OR s_docdat[] IS NOT INITIAL OR s_acckey[] IS NOT INITIAL ).

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  GET_COMPANY_CURRENCY
*&---------------------------------------------------------------------*
FORM get_company_currency USING pu_bukrs TYPE bukrs
                        CHANGING pc_waers TYPE waers.
  SELECT SINGLE waers FROM t001 INTO pc_waers WHERE bukrs = pu_bukrs.

  ENDIF.
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  GET_PARAMS
*&---------------------------------------------------------------------*
* Loads the business parameters (tax group, condition type, GL
* accounts, document type, eDocument type, program id) for PU_BUKRS
* from Y0033FI_ICM_PARM into the GV_* globals - these used to be
* hardcoded CONSTANTS, now maintained via the "Maintain Parameters"
* screen (400, admin only) instead of requiring a code change.
*---------------------------------------------------------------------*
FORM get_params USING pu_bukrs TYPE bukrs.

  SELECT SINGLE taxgrp_icms, kschl_yrb1, land1, gl_debit, gl_credit,
                doc_type, edoc_type, program_id
    FROM y0033fi_icm_parm
    INTO (@gv_taxgrp_icms, @gv_kschl_yrb1, @gv_land1, @gv_gl_debit,
          @gv_gl_credit, @gv_doc_type, @gv_edoc_type, @gv_program_id)
    WHERE bukrs = @pu_bukrs.

  IF sy-subrc <> 0.
    " No row maintained yet for this company code - fall back to the
    " original defaults so existing test setups keep working, but
    " flag it clearly since this should be maintained per BUKRS.
    gv_taxgrp_icms = 'ICMS'.
    gv_kschl_yrb1  = 'YRB1'.
    gv_land1       = 'BR'.
    gv_gl_debit    = '0018100510'.
    gv_gl_credit   = '0095018100'.
    gv_doc_type    = 'SA'.
    gv_edoc_type   = 'BR_IN_ST'.
    gv_program_id  = 'Y0033FI_ICM_STOCK_TRANSFER'.
    MESSAGE s018(y0033icms) WITH pu_bukrs.
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  GET_STATUS_FILTER_SEARCH
*&---------------------------------------------------------------------*
* Builds the status range for "Search New Candidates" from the three
* checkboxes declared in Y0033FI_ICMS_SCR_USR / _SCR_ADM (MODIF ID FS)
* - one per status a fresh search can possibly produce, before saving.
*---------------------------------------------------------------------*
FORM get_status_filter_search USING pu_sre TYPE char1
                                     pu_snc TYPE char1
                                     pu_ser TYPE char1
                            CHANGING pc_range TYPE ty_r_status.
  CLEAR pc_range.
  IF pu_sre = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-ready_to_save ) TO pc_range.
  ENDIF.
  IF pu_snc = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-not_candidate ) TO pc_range.
  ENDIF.
  IF pu_ser = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-error ) TO pc_range.
  ENDIF.
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  GET_STATUS_FILTER_VIEW
*&---------------------------------------------------------------------*
* Builds the status range for "View My Candidates" (and the admin
* review screen) from the eleven checkboxes declared in
* Y0033FI_ICMS_SCR_USR / _SCR_ADM (MODIF ID FV) - one per status a
* saved/persisted item can be in.
*---------------------------------------------------------------------*
FORM get_status_filter_view USING pu_vca TYPE char1
                                   pu_vrj TYPE char1
                                   pu_vap TYPE char1
                                   pu_vpf TYPE char1
                                   pu_vcb TYPE char1
                                   pu_vpg TYPE char1
                                   pu_vpo TYPE char1
                                   pu_vcd TYPE char1
                                   pu_vrr TYPE char1
                                   pu_vrv TYPE char1
                                   pu_ver TYPE char1
                          CHANGING pc_range TYPE ty_r_status.
  CLEAR pc_range.
  IF pu_vca = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-candidate ) TO pc_range.
  ENDIF.
  IF pu_vrj = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-rejected ) TO pc_range.
  ENDIF.
  " 021 (Auto Approved) rides on the same checkbox as 020 (Approved) -
  " same meaning for the flow (waiting for admin to post), so no extra
  " checkbox/parameter was added to the selection screens.
  IF pu_vap = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-approved ) TO pc_range.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-auto_approved ) TO pc_range.
  ENDIF.
  IF pu_vpf = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-post_failed ) TO pc_range.
  ENDIF.
  IF pu_vcb = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-cancelled_pre_post ) TO pc_range.
  ENDIF.
  IF pu_vpg = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-posting ) TO pc_range.
  ENDIF.
  IF pu_vpo = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-posted ) TO pc_range.
  ENDIF.
  IF pu_vcd = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-cancel_detected ) TO pc_range.
  ENDIF.
  IF pu_vrr = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-reversal_requested ) TO pc_range.
  ENDIF.
  IF pu_vrv = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-reversed ) TO pc_range.
  ENDIF.
  IF pu_ver = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_status-error ) TO pc_range.
  ENDIF.
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  MATCH_LANE
*&---------------------------------------------------------------------*
* Matches a set of eDocument-side fields (from EDOBRINCOMING) against
* Y0033FI_ICM_LANE, honoring blank-as-wildcard key fields. The most
* specific matching row (highest MATCH_LEVEL) wins; a tie at the top
* level is a configuration error - never guessed.
*---------------------------------------------------------------------*
FORM match_lane USING pu_key      TYPE ty_lane_key
                       pu_lt_lane TYPE ty_it_lane
              CHANGING pc_origin_region TYPE t005u-bland
                       pc_dest_region   TYPE t005u-bland
                       pc_match_level   TYPE n
                       pc_subrc         TYPE sy-subrc.

  CLEAR: pc_origin_region, pc_dest_region, pc_match_level.
  pc_subrc = 4. " default: no match

  " PU_LT_LANE is the whole Y0033FI_ICM_LANE table, read ONCE by the
  " caller (SELECT_CANDIDATE_DOCUMENTS) instead of here - this FORM
  " used to run its own SELECT on every single call (once per
  " candidate row), which was one of the main causes of a slow search
  " with many eDocuments; Y0033FI_ICM_LANE is a small config table that
  " does not change during a single search run, so reading it once and
  " filtering in memory (same conditions as the old SELECT) is both
  " safe and far cheaper.
  DATA lt_lane TYPE ty_it_lane.
  LOOP AT pu_lt_lane INTO DATA(ls_lane_row)
    WHERE active     = abap_true
      AND valid_from <= sy-datum
      AND valid_to   >= sy-datum
      AND ( bukrs         = pu_key-bukrs         OR bukrs         = space )
      AND ( vendor_code   = pu_key-vendor_code   OR vendor_code   = space )
      AND ( vendor_tax_id = pu_key-vendor_tax_id OR vendor_tax_id = space )
      AND ( vendor_region = pu_key-vendor_region OR vendor_region = space )
      AND ( country       = pu_key-country       OR country       = space )
      AND ( plant_code    = pu_key-plant_code    OR plant_code    = space )
      AND ( plant_region  = pu_key-plant_region  OR plant_region  = space )
      AND ( transfer_cfop   = pu_key-transfer_cfop   OR transfer_cfop   = space )
      AND ( transfer_branch = pu_key-transfer_branch OR transfer_branch = space ).
    APPEND ls_lane_row TO lt_lane.
  ENDLOOP.

  CHECK lt_lane IS NOT INITIAL.

  SORT lt_lane BY match_level DESCENDING.
  DATA(lv_top_level) = lt_lane[ 1 ]-match_level.
  DATA(lv_top_count) = REDUCE i( INIT n = 0
                                  FOR ls_l IN lt_lane
                                  NEXT n = n + COND #( WHEN ls_l-match_level = lv_top_level THEN 1 ELSE 0 ) ).

  IF lv_top_count > 1.
    pc_subrc = 8. " ambiguous - two equally specific rows, configuration error
    RETURN.
  ENDIF.

  DATA(ls_winner) = lt_lane[ 1 ].
  pc_origin_region = ls_winner-origin_region.
  pc_dest_region   = ls_winner-dest_region.
  pc_match_level   = ls_winner-match_level.
  pc_subrc         = 0.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  PAD_NFENUM_RANGE
*&---------------------------------------------------------------------*
* S_NFENUM accepts values typed without leading zeros (e.g. "273398"
* instead of "000273398") - pads LOW/HIGH to the field's real,
* zero-padded format via the ALPHA conversion exit, so a bare entry
* still matches. Used by both SELECT_CANDIDATE_DOCUMENTS (search) and
* REFRESH_FROM_DB (view) before filtering by NFENUM.
*---------------------------------------------------------------------*
FORM pad_nfenum_range CHANGING pc_range TYPE ty_r_nfenum.
  LOOP AT pc_range ASSIGNING FIELD-SYMBOL(<ls_nfenum>).
    IF <ls_nfenum>-low IS NOT INITIAL.
      CALL FUNCTION 'CONVERSION_EXIT_ALPHA_INPUT'
        EXPORTING input  = <ls_nfenum>-low
        IMPORTING output = <ls_nfenum>-low.
    ENDIF.
    IF <ls_nfenum>-high IS NOT INITIAL.
      CALL FUNCTION 'CONVERSION_EXIT_ALPHA_INPUT'
        EXPORTING input  = <ls_nfenum>-high
        IMPORTING output = <ls_nfenum>-high.
    ENDIF.
  ENDLOOP.
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  SELECT_CANDIDATE_DOCUMENTS
*&---------------------------------------------------------------------*
* Selects candidates from EDOCUMENT (EDOC_TYPE = BR_IN_ST, PROC_STATUS
* in COMP_OK/COMP_MAN), resolves the source nota fiscal via
* EDOBRINCOMING + J_1BNFDOC (NFENUM+SERIES+PLANT), and determines
* eligibility/origin/destination via Y0033FI_ICM_LANE - never from fixed
* screen parameters (removed) nor inferred directly from eDocument
* region fields.
*
* Cardinality rule (design decision, point 1): the NFENUM+SERIES+PLANT
* lookup against J_1BNFDOC must return EXACTLY one DOCNUM. Zero or
* multiple matches write a Y0033FI_ICM_EDOC row with STATUS = LINK_ERROR
* and do NOT become a candidate.
*---------------------------------------------------------------------*
FORM select_candidate_documents USING pu_bukrs TYPE bukrs.

  DATA(lt_nfenum) = s_nfenum[].
  PERFORM pad_nfenum_range CHANGING lt_nfenum.

  SELECT edoc_guid, proc_status, process, create_date
    FROM edocument
    INTO TABLE @DATA(lt_edoc)
    WHERE edoc_type   = @gv_edoc_type
      AND proc_status IN ( @gc_edoc_proc_status-completed_ok,
                            @gc_edoc_proc_status-completed_man )
      AND ( create_date IN @s_datum OR change_date IN @s_datum )
      AND edoc_guid IN @gr_edoc_guid.  " API only (single DOCNUM) - always empty in the report programs
  " S_DATUM matches CREATE_DATE OR CHANGE_DATE: an eDocument is often
  " created on one day and only reaches COMP_OK/COMP_MAN (the status
  " this SELECT requires) on a later day - a daily job running with
  " S_DATUM = today would otherwise never see it: on the creation day
  " it isn't completed yet, and on the day it completes its
  " CREATE_DATE is already in the past. CHANGE_DATE catches it on the
  " day it changes. Items already in an active cycle are dropped
  " later by FILTER_ACTIVE_CYCLE, so an eDocument matched again on a
  " later change never produces a duplicate candidate.
  " Field names confirmed against SE11: EDOC_GUID (key), EDOC_TYPE,
  " PROC_STATUS, CREATE_DATE. PROCESS is still assumed, not yet
  " exercised by a real test - flag if it also errors out.

  CHECK lt_edoc IS NOT INITIAL.

  SELECT edoc_guid, accesskey, company_code, materialdoc, materialdoc_year,
         nfenum, series, supplier, supplier_cnpj_cpf, supplier_cuf,
         land1, plant, plant_cuf
    FROM edobrincoming
    INTO TABLE @DATA(lt_inc)
    FOR ALL ENTRIES IN @lt_edoc
    WHERE edoc_guid = @lt_edoc-edoc_guid
      AND accesskey IN @s_acckey.
  " NOTE: do NOT filter this SELECT by EDOBRINCOMING-COMPANY_CODE = PU_BUKRS -
  " tried once, broke every candidate (that field doesn't reliably match
  " PU_BUKRS/BUKRS for legitimate rows). The real company scoping already
  " happens below, on the J_1BNFDOC read (WHERE BUKRS = PU_BUKRS) - a GUID
  " belonging to another company simply won't resolve a DOCNUM there and
  " ends up as LINK_ERROR, same as any other unresolved GUID.

  CHECK lt_inc IS NOT INITIAL.
  SORT lt_inc BY edoc_guid.

  " The following three reads used to happen ONE ROW AT A TIME inside
  " the LOOP below (one J_1BNFDOC SELECT and one Y0033FI_ICM_EDOC
  " SELECT SINGLE per eDocument, one Y0033FI_ICM_LANE SELECT per
  " candidate that got this far) - hundreds of eDocuments meant
  " hundreds of sequential round trips, the main cause of a slow
  " search. All three are now read once, in bulk, before the loop.
  "
  " EDOBRINCOMING-NFENUM/SERIES are NOT the same data elements as
  " J_1BNFDOC-NFENUM/SERIES (same names, different types/lengths - see
  " the same warning in SYNC_EDOC_TRACKING below), so FOR ALL ENTRIES
  " can't compare them directly ("fields must have the same type and
  " length"). Converting into a driving table typed against
  " J_1BNFDOC's own fields first, via VALUE (implicit MOVE
  " conversion), satisfies that check.
  TYPES: BEGIN OF ty_nfe_key,
           nfenum TYPE j_1bnfdoc-nfenum,
           series TYPE j_1bnfdoc-series,
         END OF ty_nfe_key.
  DATA lt_nfe_keys TYPE STANDARD TABLE OF ty_nfe_key WITH DEFAULT KEY.
  LOOP AT lt_inc INTO DATA(ls_inc_key).
    APPEND VALUE #( nfenum = ls_inc_key-nfenum series = ls_inc_key-series ) TO lt_nfe_keys.
  ENDLOOP.
  SORT lt_nfe_keys.
  DELETE ADJACENT DUPLICATES FROM lt_nfe_keys.

  " CANCEL <> 'X' excludes a cancelled nota fiscal right at the source -
  " a cancelled DOCNUM must never become a candidate, and excluding it
  " here also keeps it out of the cardinality count above (a cancelled
  " duplicate could otherwise push MATCH_COUNT to 2 and wrongly LINK_ERROR
  " an otherwise valid single active DOCNUM).
  SELECT docnum, nfenum, series, bukrs, branch, land1, docdat, cancel
    FROM j_1bnfdoc
    INTO TABLE @DATA(lt_all_nfdoc)
    FOR ALL ENTRIES IN @lt_nfe_keys
    WHERE nfenum = @lt_nfe_keys-nfenum
      AND series = @lt_nfe_keys-series
      AND bukrs  = @pu_bukrs
      AND direct = '1'
      AND cancel <> 'X'
      AND docnum IN @s_docnum
      AND series IN @s_series
      AND docdat IN @s_docdat.
  SORT lt_all_nfdoc BY nfenum series.

  " Origin (DIRECT=2) counterpart, same NFENUM+SERIES+BUKRS - looked up
  " in bulk here purely to record DOCNUM_ORIG alongside DOCNUM (=DOCNUM_DEST,
  " the DIRECT=1 side this FORM matches on) for traceability. Never gates
  " candidacy - the DIRECT=1 cardinality check above still decides that
  " on its own, so a missing/ambiguous DIRECT=2 counterpart just leaves
  " DOCNUM_ORIG blank instead of anything becoming a LINK_ERROR.
  SELECT docnum, nfenum, series
    FROM j_1bnfdoc
    INTO TABLE @DATA(lt_all_nfdoc_orig)
    FOR ALL ENTRIES IN @lt_nfe_keys
    WHERE nfenum = @lt_nfe_keys-nfenum
      AND series = @lt_nfe_keys-series
      AND bukrs  = @pu_bukrs
      AND direct = '2'
      AND cancel <> 'X'.
  SORT lt_all_nfdoc_orig BY nfenum series.

  SELECT edoc_guid FROM y0033fi_icm_edoc
    INTO TABLE @DATA(lt_edoc_known)
    FOR ALL ENTRIES IN @lt_edoc
    WHERE edoc_guid = @lt_edoc-edoc_guid.
  SORT lt_edoc_known BY table_line.

  " Declared explicitly (not inline @DATA(...)) so it comes out WITH
  " DEFAULT KEY, matching MATCH_LANE's PU_LT_LANE parameter type
  " (TY_IT_LANE) - an inline SELECT ... INTO TABLE @DATA(...) always
  " creates a WITH EMPTY KEY table instead, which PERFORM rejects as
  " an incompatible type even though the row type is identical.
  DATA lt_lane_all TYPE ty_it_lane.
  SELECT * FROM y0033fi_icm_lane
    INTO TABLE @lt_lane_all.

  DATA lt_candidates LIKE lt_all_nfdoc.
  DATA lt_orig_candidates LIKE lt_all_nfdoc_orig.

  LOOP AT lt_edoc INTO DATA(ls_edoc).

    READ TABLE lt_inc INTO DATA(ls_inc) WITH KEY edoc_guid = ls_edoc-edoc_guid BINARY SEARCH.
    IF sy-subrc <> 0.
      CONTINUE. " no EDOBRINCOMING row yet - covered by the "orphan" gap noted in the DDIC spec, not this form
    ENDIF.

    READ TABLE lt_edoc_known WITH KEY table_line = ls_edoc-edoc_guid TRANSPORTING NO FIELDS BINARY SEARCH.
    DATA(lv_already_known) = xsdbool( sy-subrc = 0 ).

    " Resolve DOCNUM - cardinality must be exactly 1.
    " DIRECT = 1 (Incoming) is required: both the issuing plant and
    " the receiving plant record their own copy of the same nota
    " fiscal, in opposite directions - without this filter, the
    " NFENUM+SERIES match would routinely return 2 candidates instead
    " of 1, even for a perfectly normal transfer.
    CLEAR lt_candidates.
    LOOP AT lt_all_nfdoc INTO DATA(ls_nfdoc_row) WHERE nfenum = ls_inc-nfenum AND series = ls_inc-series.
      APPEND ls_nfdoc_row TO lt_candidates.
    ENDLOOP.

    DATA lv_match_count TYPE n LENGTH 1.
    lv_match_count = COND #( WHEN lines( lt_candidates ) > 9 THEN 9 ELSE lines( lt_candidates ) ).

    IF lv_match_count <> 1.
      " STATUS = LINK_ERROR, no candidate - see FORM SYNC_EDOC_TRACKING
      " for the row upsert logic; a lightweight upsert here too so the
      " problem is visible immediately, not only after the next sync.
      PERFORM upsert_edoc_link_error USING ls_edoc-edoc_guid ls_inc lv_match_count ls_edoc-process ls_edoc-proc_status ls_inc-accesskey lv_already_known.
      CONTINUE.
    ENDIF.

    READ TABLE lt_candidates INTO DATA(ls_nfdoc) INDEX 1.

    " Track this GUID now, regardless of whether it ends up eligible
    " (lane match below) - Y0033FI_ICM_EDOC records every GUID we have
    " successfully linked, not only the ones that became candidates.
    PERFORM upsert_edoc_active USING ls_edoc-edoc_guid ls_nfdoc-docnum ls_inc ls_edoc-process ls_edoc-proc_status ls_inc-accesskey lv_already_known.

    CHECK ls_nfdoc-nfenum IN lt_nfenum. " S_NFENUM filter (screen selection, zero-padded above) - applies only to what becomes visible, not to tracking above

    " Eligibility + origin/destination via Y0033FI_ICM_LANE (Q1 resolved)
    DATA(ls_lane_key) = VALUE ty_lane_key(
      bukrs         = ls_inc-company_code
      vendor_code   = ls_inc-supplier
      vendor_tax_id = ls_inc-supplier_cnpj_cpf
      vendor_region = ls_inc-supplier_cuf
      country       = ls_inc-land1
      plant_code    = ls_inc-plant
      plant_region  = ls_inc-plant_cuf ).

    DATA lv_origin TYPE t005u-bland.
    DATA lv_dest   TYPE t005u-bland.
    DATA lv_level  TYPE n LENGTH 1.
    DATA lv_lane_subrc TYPE sy-subrc.
    PERFORM match_lane USING ls_lane_key lt_lane_all
                     CHANGING lv_origin lv_dest lv_level lv_lane_subrc.

    IF lv_lane_subrc <> 0.
      CONTINUE. " not in scope (no lane matched), or configuration error (ambiguous lanes) - neither becomes a candidate
    ENDIF.

    " Origin (DIRECT=2) counterpart - only trusted when exactly one
    " match exists for this NFENUM+SERIES, same "cardinality must be 1"
    " reasoning as the DIRECT=1 side above; left blank otherwise.
    CLEAR lt_orig_candidates.
    LOOP AT lt_all_nfdoc_orig INTO DATA(ls_orig_row) WHERE nfenum = ls_nfdoc-nfenum AND series = ls_nfdoc-series.
      APPEND ls_orig_row TO lt_orig_candidates.
    ENDLOOP.
    DATA lv_docnum_orig TYPE j_1bnfdoc-docnum.
    CLEAR lv_docnum_orig.
    IF lines( lt_orig_candidates ) = 1.
      READ TABLE lt_orig_candidates INTO DATA(ls_orig) INDEX 1.
      lv_docnum_orig = ls_orig-docnum.
    ENDIF.

    CLEAR gwa_item.
    gwa_item-docnum      = ls_nfdoc-docnum.
    gwa_item-docnum_dest = ls_nfdoc-docnum.  " this FORM matches on DIRECT=1 (destination)
    gwa_item-docnum_orig = lv_docnum_orig.
    gwa_item-nfenum       = ls_nfdoc-nfenum.
    gwa_item-series      = ls_nfdoc-series.
    gwa_item-bukrs       = ls_nfdoc-bukrs.
    gwa_item-branch      = ls_nfdoc-branch.
    gwa_item-land1       = ls_nfdoc-land1.
    gwa_item-docdat      = ls_nfdoc-docdat.
    gwa_item-cancel      = ls_nfdoc-cancel.
    gwa_item-regio_orig  = lv_origin.
    gwa_item-regio_dest  = lv_dest.
    gwa_item-lane_match_level = lv_level.
    gwa_item-werks_dest  = ls_inc-plant.
    gwa_item-edoc_guid   = ls_edoc-edoc_guid.
    gwa_item-edoc_create_date = ls_edoc-create_date.  " display only
    gwa_item-materialdoc = ls_inc-materialdoc.
    gwa_item-materialdoc_year = ls_inc-materialdoc_year.

    APPEND gwa_item TO git_item.

  ENDLOOP.

  " Single commit for every UPSERT_EDOC_ACTIVE/UPSERT_EDOC_LINK_ERROR
  " done above - those used to COMMIT WORK AND WAIT on every single
  " row themselves (a synchronous round trip per row, waiting for the
  " database to confirm each one), by far the single biggest cost in a
  " search with any real number of eDocuments.
  " API mode (GV_API_MODE): no COMMIT here - the caller owns the LUW;
  " these tracking rows are committed with the caller's own COMMIT.
  IF gv_api_mode = abap_false.
    COMMIT WORK AND WAIT.
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  SELECT_TRANSFER_CANDIDATES
*&---------------------------------------------------------------------*
* Second, independent candidate source, for the intercompany stock
* transfer flow: J_1BNFDOC itself (DIRECT = '2', emitted at the ORIGIN
* branch) is the fato gerador here - the ICMS benefit gets calculated
* right away, without waiting for the destination branch to download
* the NF-e and create an eDocument. EDOCUMENT/EDOBRINCOMING never come
* into this path at all - if/when the eDocument for this same NFe
* later shows up at the destination, SYNC_EDOC_TRACKING links it into
* Y0033FI_ICM_EDOC same as any other GUID, purely as a "confirmed
* arrival" record; it never gates this candidate.
*
* "This flow" is decided entirely by Y0033FI_ICM_LANE now, the same
* table that already decides eligibility/benefit % for this flow -
* nothing hardcoded, nothing in a separate config table:
*   - TRANSFER_BRANCH (non-blank rows) lists the origin branches in
*     scope - narrows the initial J_1BNFDOC-BRANCH read below. A
*     DEDICATED CHAR4 field, not VENDOR_CODE (CHAR10): reusing
*     VENDOR_CODE for a branch caused a real ALPHA/zero-pad conversion
*     bug ("0006" saved/read back as "0000") - see TY_LANE_KEY,
*     Y0033FI_ICMS_TOP. VENDOR_CODE stays free for its own real-vendor
*     meaning, still used as-is by the eDocument-driven flow.
*   - TRANSFER_CFOP (non-blank rows) lists the qualifying CFOPs - blank
*     = wildcard like the other LANE key fields. Narrows the
*     J_1BNFLIN read below, and the matched item's own CFOP feeds
*     MATCH_LANE per document, so a lane can require a specific CFOP
*     or accept any.
* A LANE row with blank TRANSFER_BRANCH/TRANSFER_CFOP still only
* matches THIS flow if TRANSFER_CFOP is blank too (see MATCH_LANE) -
* existing eDocument-flow rows (which never set TRANSFER_CFOP) are
* unaffected.
*
* PARID encodes the destination branch, as BUKRS (no leading zeros) +
* BRANCH - confirmed against a real document pair (BUKRS 0033/BRANCH
* 0006, PARID '330005' pointing at branch 0005, same CNPJ root
* 46.389.383 on both CGC and CNPJ_BUPLA, just a different branch
* suffix). Taking the LAST 4 characters recovers BRANCH regardless of
* how many digits BUKRS occupies - this was derived from a single
* sample document, so confirm it still holds for a company code whose
* BUKRS isn't "0033" before relying on it for real postings.
*
* MATCH_LANE itself is untouched apart from the added TRANSFER_BRANCH
* field - some of its other generic key fields are reused with a
* different meaning for this flow (lane maintenance for these rows
* keys on branch, not a real vendor):
*   TRANSFER_BRANCH = origin branch (this doc's own BRANCH)
*   VENDOR_CODE   = blank - not used by this flow, left free for the
*                   eDocument flow's real-vendor meaning
*   VENDOR_TAX_ID = origin CNPJ (CNPJ_BUPLA)
*   VENDOR_REGION = blank - not on the header for the origin side;
*                   TRANSFER_BRANCH above is already an exact,
*                   unambiguous key on its own
*   PLANT_CODE    = destination branch (from PARID) - not a real plant
*                   (WERKS) yet, see the T001W lookup below
*   PLANT_REGION  = destination region - already on the header
*                   (J_1BNFDOC-REGIO is the BR partner's own region)
*---------------------------------------------------------------------*
FORM select_transfer_candidates USING pu_bukrs TYPE bukrs.

  " S_DATUM (eDocument creation date) and S_ACCKEY (NF-e access key of
  " the eDocument) are eDocument filters - this model has no eDocument
  " at all, so nothing it finds can match them. Filled = this model
  " returns nothing, instead of silently ignoring them and returning
  " every transfer nota of the company (a user-cockpit search with only
  " S_DATUM filled once returned ~69k items this way).
  IF s_datum[] IS NOT INITIAL OR s_acckey[] IS NOT INITIAL.
    RETURN.
  ENDIF.

  DATA lt_lane_all TYPE ty_it_lane.
  SELECT * FROM y0033fi_icm_lane
    INTO TABLE @lt_lane_all.

  " Candidate origin branches = every non-blank TRANSFER_BRANCH
  " configured for this BUKRS - narrows the J_1BNFDOC read below. A
  " blank TRANSFER_BRANCH (wildcard) can't narrow anything and is
  " excluded here; it's still honored later, per document, by
  " MATCH_LANE itself.
  TYPES ty_r_branch TYPE RANGE OF j_1bnfdoc-branch.
  DATA lr_branch TYPE ty_r_branch.
  LOOP AT lt_lane_all INTO DATA(ls_lane_b)
    WHERE bukrs = pu_bukrs AND transfer_branch IS NOT INITIAL.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = ls_lane_b-transfer_branch ) TO lr_branch.
  ENDLOOP.
  SORT lr_branch.
  DELETE ADJACENT DUPLICATES FROM lr_branch.
  CHECK lr_branch IS NOT INITIAL. " nothing configured for this flow at this BUKRS

  " Candidate CFOPs = every non-blank TRANSFER_CFOP configured for this
  " BUKRS - narrows the J_1BNFLIN read below. Same wildcard reasoning
  " as VENDOR_CODE above.
  TYPES ty_r_cfop TYPE RANGE OF char10.
  DATA lr_cfop TYPE ty_r_cfop.
  LOOP AT lt_lane_all INTO DATA(ls_lane_c)
    WHERE bukrs = pu_bukrs AND transfer_cfop IS NOT INITIAL.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = ls_lane_c-transfer_cfop ) TO lr_cfop.
  ENDLOOP.
  SORT lr_cfop.
  DELETE ADJACENT DUPLICATES FROM lr_cfop.
  CHECK lr_cfop IS NOT INITIAL.

  DATA(lt_nfenum) = s_nfenum[].
  PERFORM pad_nfenum_range CHANGING lt_nfenum.

  " CANCEL <> 'X' - same reasoning as SELECT_CANDIDATE_DOCUMENTS: a
  " cancelled DOCNUM must never become a candidate here either.
  SELECT docnum, nfenum, series, bukrs, branch, land1, docdat, cancel,
         parid, regio, cnpj_bupla
    FROM j_1bnfdoc
    INTO TABLE @DATA(lt_transfer)
    WHERE bukrs  = @pu_bukrs
      AND direct = '2'
      AND cancel <> 'X'
      AND branch IN @lr_branch
      AND nfenum IN @lt_nfenum
      AND docnum IN @s_docnum
      AND series IN @s_series
      AND docdat IN @s_docdat.

  CHECK lt_transfer IS NOT INITIAL.

  " Only NF-e already authorized by SEFAZ: J_1BNFE_ACTIVE-DOCSTA = 1
  " (authorized) AND CODE = 100 ("Autorizado o uso da NF-e"). A nota
  " still waiting, rejected or denied at SEFAZ is not a candidate yet -
  " it becomes one in a later search, once it is authorized.
  SELECT docnum FROM j_1bnfe_active
    INTO TABLE @DATA(lt_nfe_authorized)
    FOR ALL ENTRIES IN @lt_transfer
    WHERE docnum = @lt_transfer-docnum
      AND docsta = '1'
      AND code   = '100'.
  SORT lt_nfe_authorized BY table_line.
  LOOP AT lt_transfer INTO DATA(ls_nfe_chk).
    READ TABLE lt_nfe_authorized TRANSPORTING NO FIELDS BINARY SEARCH
      WITH KEY table_line = ls_nfe_chk-docnum.
    IF sy-subrc <> 0.
      DELETE lt_transfer.
    ENDIF.
  ENDLOOP.
  CHECK lt_transfer IS NOT INITIAL.

  " Destination (DIRECT=1) counterpart, same NFENUM+SERIES+BUKRS - bulk
  " lookup purely to record DOCNUM_DEST alongside DOCNUM (=DOCNUM_ORIG,
  " the DIRECT=2 side this FORM matches on) for traceability. Never
  " gates candidacy - same "informative only" reasoning as DOCNUM_ORIG
  " in SELECT_CANDIDATE_DOCUMENTS.
  SELECT docnum, nfenum, series
    FROM j_1bnfdoc
    INTO TABLE @DATA(lt_transfer_dest)
    FOR ALL ENTRIES IN @lt_transfer
    WHERE nfenum = @lt_transfer-nfenum
      AND series = @lt_transfer-series
      AND bukrs  = @pu_bukrs
      AND direct = '1'
      AND cancel <> 'X'.
  SORT lt_transfer_dest BY nfenum series.

  " Only notas with at least one line item at a configured CFOP belong
  " to this flow - that item's own CFOP (not just its existence) feeds
  " the LANE match below, one row per DOCNUM (first qualifying line
  " wins if a nota mixes CFOPs - same "one match per document"
  " simplification the rest of this FORM already relies on).
  TYPES: BEGIN OF ty_cfop_hit,
           docnum TYPE j_1bnflin-docnum,
           cfop   TYPE j_1bnflin-cfop,
         END OF ty_cfop_hit.
  DATA lt_cfop_hit TYPE STANDARD TABLE OF ty_cfop_hit WITH DEFAULT KEY.
  SELECT docnum, cfop FROM j_1bnflin
    INTO TABLE @lt_cfop_hit
    FOR ALL ENTRIES IN @lt_transfer
    WHERE docnum = @lt_transfer-docnum
      AND cfop   IN @lr_cfop.
  SORT lt_cfop_hit BY docnum.
  DELETE ADJACENT DUPLICATES FROM lt_cfop_hit COMPARING docnum.

  LOOP AT lt_transfer INTO DATA(ls_nfdoc).

    READ TABLE lt_cfop_hit INTO DATA(ls_cfop_hit) WITH KEY docnum = ls_nfdoc-docnum BINARY SEARCH.
    IF sy-subrc <> 0.
      CONTINUE. " no qualifying CFOP line on this nota
    ENDIF.

    " Destination branch = last 4 characters of PARID (see the header
    " comment on the BUKRS+BRANCH convention).
    DATA lv_off TYPE i.
    lv_off = strlen( ls_nfdoc-parid ) - 4.
    DATA(lv_dest_branch) = ls_nfdoc-parid+lv_off(4).

    DATA(ls_lane_key) = VALUE ty_lane_key(
      bukrs           = ls_nfdoc-bukrs
      vendor_code     = space
      vendor_tax_id   = ls_nfdoc-cnpj_bupla
      vendor_region   = space
      country         = ls_nfdoc-land1
      plant_code      = lv_dest_branch
      plant_region    = ls_nfdoc-regio
      transfer_cfop   = ls_cfop_hit-cfop
      transfer_branch = ls_nfdoc-branch ).

    DATA lv_origin TYPE t005u-bland.
    DATA lv_dest   TYPE t005u-bland.
    DATA lv_level  TYPE n LENGTH 1.
    DATA lv_lane_subrc TYPE sy-subrc.
    PERFORM match_lane USING ls_lane_key lt_lane_all
                     CHANGING lv_origin lv_dest lv_level lv_lane_subrc.

    IF lv_lane_subrc <> 0.
      CONTINUE. " not in scope (no lane matched), or configuration error (ambiguous lanes)
    ENDIF.

    " Real plant (WERKS), needed only for the eventual FI posting
    " (Y0033FI_ICMS_F02 - POST_RELEASED_ITEMS sets the GL line's plant
    " from WERKS_DEST) - not needed for the lane match above, which
    " works off branch codes directly. Looked up only for candidates
    " that already passed the lane match, so this stays a cheap
    " SELECT SINGLE, not a bulk concern like SELECT_CANDIDATE_DOCUMENTS.
    " T001W has no BUKRS field at all (plant-to-company-code linkage
    " is indirect, via T001K/T001) - J_1BBRANCH alone is the lookup key
    " here, since Business Place codes are unique per plant regardless
    " of company code.
    DATA lv_werks_dest TYPE werks_d.
    CLEAR lv_werks_dest.
    SELECT SINGLE werks FROM t001w
      INTO @lv_werks_dest
      WHERE j_1bbranch = @lv_dest_branch.

    " Destination (DIRECT=1) counterpart - only trusted when exactly one
    " match exists for this NFENUM+SERIES, same cardinality reasoning as
    " SELECT_CANDIDATE_DOCUMENTS; left blank otherwise.
    DATA lt_dest_candidates LIKE lt_transfer_dest.
    CLEAR lt_dest_candidates.
    LOOP AT lt_transfer_dest INTO DATA(ls_dest_row) WHERE nfenum = ls_nfdoc-nfenum AND series = ls_nfdoc-series.
      APPEND ls_dest_row TO lt_dest_candidates.
    ENDLOOP.
    DATA lv_docnum_dest TYPE j_1bnfdoc-docnum.
    CLEAR lv_docnum_dest.
    IF lines( lt_dest_candidates ) = 1.
      READ TABLE lt_dest_candidates INTO DATA(ls_dest) INDEX 1.
      lv_docnum_dest = ls_dest-docnum.
    ENDIF.

    CLEAR gwa_item.
    gwa_item-docnum      = ls_nfdoc-docnum.
    gwa_item-docnum_orig = ls_nfdoc-docnum.  " this FORM matches on DIRECT=2 (origin)
    gwa_item-docnum_dest = lv_docnum_dest.
    gwa_item-nfenum      = ls_nfdoc-nfenum.
    gwa_item-series      = ls_nfdoc-series.
    gwa_item-bukrs       = ls_nfdoc-bukrs.
    gwa_item-branch      = ls_nfdoc-branch.
    gwa_item-land1       = ls_nfdoc-land1.
    gwa_item-docdat      = ls_nfdoc-docdat.
    gwa_item-cancel      = ls_nfdoc-cancel.
    gwa_item-regio_orig  = lv_origin.
    gwa_item-regio_dest  = lv_dest.
    gwa_item-lane_match_level = lv_level.
    gwa_item-werks_dest  = lv_werks_dest.
    " EDOC_GUID/MATERIALDOC(_YEAR) stay blank - no eDocument involved
    " at this point; SYNC_EDOC_TRACKING fills EDOC_GUID in later if and
    " when one shows up for this same NFe at the destination.

    APPEND gwa_item TO git_item.

  ENDLOOP.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  UPSERT_EDOC_LINK_ERROR
*&---------------------------------------------------------------------*
* Records a GUID that failed to resolve to exactly one DOCNUM.
*---------------------------------------------------------------------*
FORM upsert_edoc_link_error USING pu_edoc_guid TYPE char32
                                   pu_inc       TYPE any
                                   pu_match_count TYPE n
                                   pu_process   TYPE char10
                                   pu_status    TYPE char10
                                   pu_accesskey TYPE char44
                                   pu_already_known TYPE abap_bool.

  " PU_ALREADY_KNOWN comes from a single bulk lookup the caller
  " (SELECT_CANDIDATE_DOCUMENTS) already did for every eDocument in

    INSERT y0033fi_icm_edoc FROM @( VALUE #(
      edoc_guid       = pu_edoc_guid
      match_count     = pu_match_count
      accesskey       = pu_accesskey
      edoc_process    = pu_process
      edoc_status     = pu_status
      status          = gc_edoc_status-link_error
      first_seen_date = sy-datum
      first_seen_time = sy-uzeit
      last_seen_date  = sy-datum
      last_seen_time  = sy-uzeit ) ).
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  SYNC_EDOC_TRACKING
*&---------------------------------------------------------------------*
* Keeps Y0033FI_ICM_EDOC in sync with EDOCUMENT/EDOBRINCOMING for the
* notas fiscais we already know about (any DOCNUM present in
* Y0033FI_ICM_ITEM): marks new GUIDs as ACTIVE, refreshes LAST_SEEN for
* GUIDs still found, and flags GUIDs no longer found as DELETED.
* Called together with CHECK_NF_CANCELLATION (button and job).
*
* Table is keyed by EDOC_GUID only (see CR16002_DDIC_SPEC.md) - a GUID
* that never resolved to a DOCNUM is handled by
* FORM UPSERT_EDOC_LINK_ERROR instead, not here.
*
* Does NOT create new candidates and does NOT touch Y0033FI_ICM_ITEM - a
* new eDoc for a nota with an active cycle is only tracked here for
* visibility (see design discussion, scenario 3); it becomes eligible
* as a fresh candidate only through FILTER_ACTIVE_CYCLE, the normal
* way, once the prior cycle reaches REVERSED.
*---------------------------------------------------------------------*
FORM sync_edoc_tracking.

  SELECT DISTINCT docnum, nfenum, series, bukrs
    FROM y0033fi_icm_item
    INTO TABLE @DATA(lt_docnum).
  CHECK lt_docnum IS NOT INITIAL.

  LOOP AT lt_docnum INTO DATA(ls_doc).

    " Per-DOCNUM lookup (not FOR ALL ENTRIES) - sidesteps the strict
    " type/length match FOR ALL ENTRIES requires between comparison
    " fields; EDOBRINCOMING-NFENUM and Y0033FI_ICM_ITEM-NFENUM come
    " from different data elements (J_1BNFDOC-NFENUM vs EDOBRINCOMING's
    " own type) and are not guaranteed to match exactly, even though
    " both fields are now named the same. Volume here is the set of
    " notas we already track, not a mass selection, so the extra round
    " trips are acceptable.
    SELECT i~edoc_guid, i~accesskey, i~materialdoc, i~materialdoc_year,
           e~process, e~proc_status
      FROM edobrincoming AS i
      INNER JOIN edocument AS e ON e~edoc_guid = i~edoc_guid
      INTO TABLE @DATA(lt_now_raw)
      WHERE i~nfenum    = @ls_doc-nfenum
        AND i~series    = @ls_doc-series
        AND e~edoc_type = @gv_edoc_type.

    DATA(lt_now_for_doc) = VALUE ty_it_edoc( ).
    LOOP AT lt_now_raw INTO DATA(ls_now).
      APPEND VALUE ty_edoc( docnum       = ls_doc-docnum
                             edoc_guid   = ls_now-edoc_guid
                             match_count = 1
                             accesskey   = ls_now-accesskey
                             materialdoc = ls_now-materialdoc
                             materialdoc_year = ls_now-materialdoc_year
                             edoc_process = ls_now-process
                             edoc_status  = ls_now-proc_status )
             TO lt_now_for_doc.
    ENDLOOP.

    SELECT * FROM y0033fi_icm_edoc INTO TABLE @DATA(lt_known)
      WHERE docnum = @ls_doc-docnum
        AND status = @gc_edoc_status-active.

    " New or still-present GUIDs
    LOOP AT lt_now_for_doc INTO DATA(ls_seen).
      READ TABLE lt_known WITH KEY edoc_guid = ls_seen-edoc_guid TRANSPORTING NO FIELDS.
      IF sy-subrc = 0.
        UPDATE y0033fi_icm_edoc SET last_seen_date = @sy-datum,
                                    last_seen_time = @sy-uzeit
          WHERE edoc_guid = @ls_seen-edoc_guid.
      ELSE.
        INSERT y0033fi_icm_edoc FROM @( VALUE #(
          docnum         = ls_doc-docnum
          edoc_guid      = ls_seen-edoc_guid
          match_count    = 1
          accesskey      = ls_seen-accesskey
          materialdoc    = ls_seen-materialdoc
          materialdoc_year = ls_seen-materialdoc_year
          seqnr          = 0
          edoc_process   = ls_seen-edoc_process
          edoc_status    = ls_seen-edoc_status
          status         = gc_edoc_status-active
          first_seen_date = sy-datum
          first_seen_time = sy-uzeit
          last_seen_date  = sy-datum
          last_seen_time  = sy-uzeit ) ).
      ENDIF.
    ENDLOOP.

    " GUIDs we knew as ACTIVE but no longer find -> DELETED
    LOOP AT lt_known INTO DATA(ls_gone).
      READ TABLE lt_now_for_doc WITH KEY edoc_guid = ls_gone-edoc_guid TRANSPORTING NO FIELDS.
      IF sy-subrc <> 0.
        DATA(lv_backup_ref) = space.
        " TODO: Y0000FI_EDOC's key field name is not confirmed yet -
        " the backup cross-reference lookup is stubbed out (no SELECT
        " against Y0000FI_EDOC) so this form compiles cleanly. Once
        " you confirm the field name, uncomment/adjust a lookup here
        " and populate LV_BACKUP_REF accordingly.

        UPDATE y0033fi_icm_edoc SET status        = @gc_edoc_status-deleted,
                                    del_det_date  = @sy-datum,
                                    del_det_time  = @sy-uzeit,
                                    del_det_user  = @sy-uname,
                                    backup_ref    = @lv_backup_ref
          WHERE edoc_guid = @ls_gone-edoc_guid.
      ENDIF.
    ENDLOOP.

  ENDLOOP.

  COMMIT WORK AND WAIT.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  GET_LATEST_EDOC_GUID
*&---------------------------------------------------------------------*
* Returns the most recently seen eDocument GUID for a nota fiscal,
* regardless of ACTIVE/DELETED (but never LINK_ERROR, which by
* definition has no DOCNUM to match on) - used to populate the ALV
* display field (see design discussion: "always show the last
* eDocument found for that nota fiscal").
*---------------------------------------------------------------------*
FORM get_latest_edoc_guid USING pu_docnum TYPE j_1bnfdoc-docnum
                        CHANGING pc_edoc_guid TYPE char32.

  SELECT edoc_guid FROM y0033fi_icm_edoc
    INTO TABLE @DATA(lt_guid)
    UP TO 1 ROWS
    WHERE docnum = @pu_docnum
      AND status <> @gc_edoc_status-link_error
    ORDER BY last_seen_date DESCENDING, last_seen_time DESCENDING.

  IF lines( lt_guid ) > 0.
    pc_edoc_guid = lt_guid[ 1 ]-edoc_guid.
  ELSE.
    CLEAR pc_edoc_guid.
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  READ_ITEMS_AND_ICMS
*&---------------------------------------------------------------------*
* TODO (Q6): rule for multiple ICMS lines per item still pending -
* this version takes the first line and flags the rest as ERROR.
*---------------------------------------------------------------------*
FORM read_items_and_icms.

  DATA lt_result TYPE ty_it_item.

  LOOP AT git_item INTO gwa_item.

    SELECT itmnum, matnr, matorg, menge, meins, netwr, mwskz, prctr, cfop
      FROM j_1bnflin
      INTO TABLE @DATA(lt_lin)
      WHERE docnum = @gwa_item-docnum.

    LOOP AT lt_lin INTO DATA(ls_lin).

      SELECT taxgrp, base, excbas, othbas, rate, taxval
        FROM j_1bnfstx
        INTO TABLE @DATA(lt_stx)
        WHERE docnum = @gwa_item-docnum
          AND itmnum = @ls_lin-itmnum
          AND taxgrp = @gv_taxgrp_icms.

      DATA(lv_lines) = lines( lt_stx ).
      DATA(ls_out) = gwa_item.
      ls_out-itmnum = ls_lin-itmnum.
      ls_out-matnr  = ls_lin-matnr.
      ls_out-matorg = ls_lin-matorg.
      ls_out-menge  = ls_lin-menge.
      ls_out-menge_unit = ls_lin-meins.
      ls_out-netwr  = ls_lin-netwr.
      ls_out-mwskz  = ls_lin-mwskz.
      ls_out-prctr  = ls_lin-prctr.
      ls_out-cfop   = ls_lin-cfop.

      IF lv_lines = 0.
        ls_out-status = gc_status-error.
        ls_out-msg    = 'No ICMS line found in J_1BNFSTX for this item'.
      ELSEIF lv_lines > 1.
        ls_out-status = gc_status-error.
        DATA lv_msg_lines TYPE char100.
        lv_msg_lines = |Item has { lv_lines } ICMS lines - selection rule pending (Q6)|.
        ls_out-msg    = lv_msg_lines.
        READ TABLE lt_stx INTO DATA(ls_stx1) INDEX 1.
        ls_out-icms_base = ls_stx1-base.
        ls_out-icms_excbas = ls_stx1-excbas.
        ls_out-icms_othbas = ls_stx1-othbas.
        ls_out-icms_rate = ls_stx1-rate.
        ls_out-icms_val  = ls_stx1-taxval.
        ls_out-stx_seq   = 1.
      ELSE.
        READ TABLE lt_stx INTO DATA(ls_stx) INDEX 1.
        ls_out-icms_base = ls_stx-base.
        ls_out-icms_excbas = ls_stx-excbas.
        ls_out-icms_othbas = ls_stx-othbas.
        ls_out-icms_rate = ls_stx-rate.
        ls_out-icms_val  = ls_stx-taxval.
        ls_out-stx_seq   = 1.
        ls_out-line_ok   = abap_true.  " pipeline-internal marker - see TY_ITEM-LINE_OK
      ENDIF.

      APPEND ls_out TO lt_result.
    ENDLOOP.

  ENDLOOP.

  git_item = lt_result.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  DETERMINE_BENEFIT_PERCENTAGE
*&---------------------------------------------------------------------*
* TODO (Q7): real condition access technique pending - approximated
* via KONH/KONP by KSCHL.
* TODO (Q8): validity reference date pending - uses DOCDAT for now.
* TODO (Q9): sign/scale handling pending - ABS() applied.
* TODO (Q10): Release Status not filtered yet.
* TODO (Q11): missing/ambiguous condition blocks the item (status ERROR).
* TODO (Q12): zero percentage kept visible, not excluded.
*---------------------------------------------------------------------*
FORM determine_benefit_percentage.

  LOOP AT git_item INTO gwa_item WHERE line_ok = abap_true.
    DATA(lv_tabix) = sy-tabix.

    " Confirmed access table for YRB1: A607 (Country/Ship from/Ship
    " to/Origin) - key fields ALAND, TXREG_SF, TXREG_ST, MTORG, plus
    " KSCHL/validity. This replaces the earlier approach (reading
    " every YRB1 record in KONH with no key filter), which was
    " confirmed to return wrong/non-deterministic percentages.
    SELECT SINGLE knumh, datab, datbi
      FROM a607
      INTO (@DATA(lv_knumh), @DATA(lv_datab), @DATA(lv_datbi))
      WHERE kschl    = @gv_kschl_yrb1
        AND aland    = @gwa_item-land1
        AND txreg_sf = @gwa_item-regio_orig
        AND txreg_st = @gwa_item-regio_dest
        AND mtorg    = @gwa_item-matorg
        AND datab   <= @gwa_item-docdat
        AND datbi   >= @gwa_item-docdat.

    DATA(lv_found) = abap_false.

    IF sy-subrc = 0.
      SELECT SINGLE kbetr, kpein, kmein FROM konp
        INTO (@DATA(lv_kbetr), @DATA(lv_kpein), @DATA(lv_kmein))
        WHERE knumh = @lv_knumh
          AND kschl = @gv_kschl_yrb1.

      " A607 row matched but KONP has no rate (or rate is exactly
      " zero) - treat as not found rather than silently accepting 0,
      " same reasoning as before.
      IF sy-subrc = 0 AND lv_kbetr <> 0.
        gwa_item-kschl  = gv_kschl_yrb1.
        gwa_item-knumh  = lv_knumh.
        gwa_item-datab  = lv_datab.
        gwa_item-datbi  = lv_datbi.
        gwa_item-benefit_percent = abs( lv_kbetr ) / 10.  " KONP-KBETR for
        " percentage conditions is stored with one extra decimal place
        " (SAP standard behavior: KBETR is a CURR field with 2
        " decimals, percentages need 3, so SAP stores x10 and divides
        " by 10 on display) - confirmed against real data (Q9 resolved).
        gwa_item-kpein  = lv_kpein.
        gwa_item-kmein  = lv_kmein.
        lv_found = abap_true.
      ENDIF.
    ENDIF.

    IF lv_found = abap_false.
      gwa_item-status = gc_status-error.
      gwa_item-msg    = 'YRB1 condition not found/not valid for this key (TODO Q11)'.
    ENDIF.

    MODIFY git_item FROM gwa_item INDEX lv_tabix.
  ENDLOOP.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  FILTER_ACTIVE_CYCLE
*&---------------------------------------------------------------------*
* Blocks a new candidate (new SEQNR) for DOCNUM+ITMNUM combos that
* already have an active cycle (any SEQNR not yet REVERSED). See
* "Note on re-assessment (SEQNR)" in CR16002_DDIC_SPEC.md.
*---------------------------------------------------------------------*
FORM filter_active_cycle.

  " "Search New Candidates" should only ever show items that are
  " genuinely not yet tracked - anything with an active cycle already
  " belongs in "View My Candidates" (which the user can filter
  " themselves), so it is removed here entirely rather than shown
  " with its real status. Mixing the two was confusing: a re-run of
  " Search New used to show already-saved items alongside brand new
  " ones, both under the same STATUS column.
  DATA lt_remove_idx TYPE TABLE OF sy-tabix.

  LOOP AT git_item INTO gwa_item WHERE line_ok = abap_true.
    DATA(lv_tabix) = sy-tabix.

    " REVERSED and REJECTED are both "closed" outcomes - like a
    " reversed posting, a rejected candidate should not permanently
    " block the same nota/item from becoming a fresh candidate again
    " in a later search.
    SELECT SINGLE @abap_true FROM y0033fi_icm_item INTO @DATA(lv_exists)
      WHERE docnum = @gwa_item-docnum
        AND itmnum = @gwa_item-itmnum
        AND status <> @gc_status-reversed
        AND status <> @gc_status-rejected
        AND status <> @gc_status-cancelled_pre_post.

    IF sy-subrc = 0.
      APPEND lv_tabix TO lt_remove_idx.
    ENDIF.
  ENDLOOP.

  SORT lt_remove_idx DESCENDING.
  LOOP AT lt_remove_idx INTO DATA(lv_idx).
    DELETE git_item INDEX lv_idx.
  ENDLOOP.

ENDFORM.

ENDFORM.

      MODIFY git_item FROM gwa_item INDEX lv_tabix.
    ENDIF.
  ENDLOOP.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  BUILD_NOTA_COLOR
*&---------------------------------------------------------------------*
* Alternates a light background tint on the NFe Date/NFe Number/Item/
* DocNum cells every time the nota fiscal changes going down GIT_ITEM,
* so it's easy to spot where one nota's items end and the next one's
* begin.
*
* GIT_ITEM is physically re-sorted here first (NFe Date / NFe Number /
* Cycle / Item, all ascending, matching BUILD_SORT_TABLE) instead of relying
* on GT_SORT alone - GT_SORT only tells the ALV control how to display
* the data, it does NOT reorder the underlying internal table, so
* grouping change detection below would otherwise walk GIT_ITEM in
* whatever order it happened to be built (DB read order), not the
* order actually shown on screen - the exact cause of colors looking
* "wrong"/not grouped. If the user manually re-sorts the grid by
* clicking another column header, each row keeps the color assigned
* here (color travels with the row), so it stops looking grouped but
* is never wrong for that row's own nota fiscal.
*---------------------------------------------------------------------*
FORM build_nota_color.

  SORT git_item BY docdat ASCENDING nfenum ASCENDING seqnr ASCENDING itmnum ASCENDING.

  DATA lv_last_nfenum TYPE j_1bnfdoc-nfenum.
  DATA lv_first_row   TYPE abap_bool VALUE abap_true.
  DATA lv_color_col   TYPE i.

  LOOP AT git_item INTO gwa_item.
    DATA(lv_tabix) = sy-tabix.

    IF lv_first_row = abap_true OR gwa_item-nfenum <> lv_last_nfenum.
      lv_first_row   = abap_false.
      lv_last_nfenum = gwa_item-nfenum.
      " Flip between "no tint" (0) and COL_POSITIVE (5, green) each
      " time the nota fiscal changes.
      IF lv_color_col = 5.
        lv_color_col = 0.
      ELSE.
        lv_color_col = 5.
      ENDIF.
    ENDIF.

    CLEAR gwa_item-color_tab.
    IF lv_color_col <> 0.
      APPEND VALUE #( fname = 'DOCDAT' color-col = lv_color_col color-int = 0 color-inv = 0 )
        TO gwa_item-color_tab.
      APPEND VALUE #( fname = 'NFENUM' color-col = lv_color_col color-int = 0 color-inv = 0 )
        TO gwa_item-color_tab.
      APPEND VALUE #( fname = 'ITMNUM' color-col = lv_color_col color-int = 0 color-inv = 0 )
        TO gwa_item-color_tab.
      APPEND VALUE #( fname = 'DOCNUM' color-col = lv_color_col color-int = 0 color-inv = 0 )
        TO gwa_item-color_tab.
    ENDIF.
    MODIFY git_item FROM gwa_item INDEX lv_tabix TRANSPORTING color_tab.
  ENDLOOP.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  BUILD_STATUS_ICONS
*&---------------------------------------------------------------------*
* Maps each item's STATUS to a traffic-light icon shown in its own
* ALV column (STATUS_ICON, see BUILD_FIELDCAT) - STATUS_DESCR (see
* BUILD_STATUS_DESCR) stays as-is, this is just a quick visual cue
* alongside it. Icon names confirmed against this system's icon list
* (transaction ICON) before use.
*---------------------------------------------------------------------*
FORM build_status_icons.

  LOOP AT git_item INTO gwa_item.
    DATA(lv_tabix) = sy-tabix.

    CASE gwa_item-status.
      WHEN gc_status-ready_to_save.
        gwa_item-status_icon = icon_system_play.        " not saved yet (blue - distinct from NOT_CANDIDATE below)
      WHEN gc_status-candidate.
        gwa_item-status_icon = icon_led_yellow.          " waiting for user approval
      WHEN gc_status-rejected.
        gwa_item-status_icon = icon_led_inactive.        " closed out, no action possible - user chose not to proceed
      WHEN gc_status-approved OR gc_status-auto_approved.
        gwa_item-status_icon = icon_checked.              " waiting for admin to post
      WHEN gc_status-post_failed.
        gwa_item-status_icon = icon_message_warning.     " attempted, failed - see MSG; retry candidate, same as APPROVED
      WHEN gc_status-cancelled_pre_post.
        gwa_item-status_icon = icon_cancel.              " source nota cancelled before this item ever posted - terminal, no accounting document exists
      WHEN gc_status-posting.
        gwa_item-status_icon = icon_locked.              " transient posting lock
      WHEN gc_status-posted.
        gwa_item-status_icon = icon_led_green.            " done
      WHEN gc_status-cancel_detected.
        gwa_item-status_icon = icon_alert.               " needs attention
      WHEN gc_status-reversal_requested.
        gwa_item-status_icon = icon_history.             " waiting for admin to execute reversal
      WHEN gc_status-reversed.
        gwa_item-status_icon = icon_led_red.              " closed out
      WHEN gc_status-error.
        gwa_item-status_icon = icon_message_error.       " blocked
      WHEN gc_status-not_candidate.
        gwa_item-status_icon = icon_led_inactive.        " nothing to offer here, not an error
      WHEN OTHERS.
        CLEAR gwa_item-status_icon.
    ENDCASE.

    MODIFY git_item FROM gwa_item INDEX lv_tabix TRANSPORTING status_icon.
  ENDLOOP.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  STATUS_CODE_TO_DESCR
*&---------------------------------------------------------------------*
* "<code> - <description>" for one status value (e.g. "010 -
* Candidate") - single source of truth for BUILD_STATUS_DESCR and
* SHOW_LOG_POPUP, so the two can't drift. Blank in, blank out (a
* blank STATUS_FROM/STATUS_TO in the log is legitimate, not an error
* - see WRITE_LOG).
*---------------------------------------------------------------------*
FORM status_code_to_descr USING    pu_status TYPE y0033fi_icm_status_n
                           CHANGING pc_descr  TYPE char40.
  CLEAR pc_descr.

  CASE pu_status.
    WHEN gc_status-candidate.          pc_descr = |{ pu_status } - Candidate|.
    WHEN gc_status-rejected.           pc_descr = |{ pu_status } - Rejected|.
    WHEN gc_status-approved.           pc_descr = |{ pu_status } - Approved|.
    WHEN gc_status-auto_approved.      pc_descr = |{ pu_status } - Auto Approved|.
    WHEN gc_status-post_failed.        pc_descr = |{ pu_status } - Post Failed|.
    WHEN gc_status-cancelled_pre_post. pc_descr = |{ pu_status } - Cancelled Before Posting|.
    WHEN gc_status-posting.            pc_descr = |{ pu_status } - Posting|.
    WHEN gc_status-posted.             pc_descr = |{ pu_status } - Posted|.
    WHEN gc_status-cancel_detected.    pc_descr = |{ pu_status } - Cancel Detected|.
    WHEN gc_status-reversal_requested. pc_descr = |{ pu_status } - Reversal Requested|.
    WHEN gc_status-reversed.           pc_descr = |{ pu_status } - Reversed|.
    WHEN gc_status-ready_to_save.      pc_descr = |{ pu_status } - Ready to Save|.
    WHEN gc_status-not_candidate.      pc_descr = |{ pu_status } - Not a Candidate|.
    WHEN gc_status-error.              pc_descr = |{ pu_status } - Error|.
    WHEN OTHERS.                       CLEAR pc_descr.
  ENDCASE.

*&---------------------------------------------------------------------*
*&      Form  ENSURE_FULL_DOCNUM_SELECTION
*&---------------------------------------------------------------------*
* In practice, an action should apply to every item of a nota fiscal
* (DOCNUM), not just some of them. If the user ticked only part of a
* DOCNUM's rows, ask once (covering every affected DOCNUM in a single
* question) whether to select every item of those documents, and do
* so on "Yes". Answering "No" leaves the selection exactly as the
* user made it - this is a convenience prompt, not a hard block, so
* the underlying action (SAVE/APPROVE/DEL_CAND/REQ_REV) still runs
* against whatever GIT_ITEM-SEL ends up being.
*---------------------------------------------------------------------*
FORM ensure_full_docnum_selection.

  DATA lt_docnum TYPE STANDARD TABLE OF j_1bdocnum WITH DEFAULT KEY.
  LOOP AT git_item INTO DATA(ls_sel) WHERE sel = abap_true.
    READ TABLE lt_docnum WITH KEY table_line = ls_sel-docnum TRANSPORTING NO FIELDS.
    IF sy-subrc <> 0.
      APPEND ls_sel-docnum TO lt_docnum.
    ENDIF.
  ENDLOOP.
  CHECK lt_docnum IS NOT INITIAL.

  " Keep only the DOCNUMs that have at least one UNselected row too -
  " a DOCNUM already fully selected needs no prompt.
  DATA lt_incomplete TYPE STANDARD TABLE OF j_1bdocnum WITH DEFAULT KEY.
  LOOP AT lt_docnum INTO DATA(lv_docnum).
    READ TABLE git_item TRANSPORTING NO FIELDS
      WITH KEY docnum = lv_docnum sel = abap_false.
    IF sy-subrc = 0.
      APPEND lv_docnum TO lt_incomplete.
    ENDIF.
  ENDLOOP.
  CHECK lt_incomplete IS NOT INITIAL.

  DATA lv_answer TYPE char1.
  CALL FUNCTION 'POPUP_TO_CONFIRM'
    EXPORTING
      titlebar       = 'Partial nota fiscal selection'
      text_question  = |{ lines( lt_incomplete ) } nota fiscal(s) have some items not selected. Select all items of these documents?|
      text_button_1  = 'Yes'
      text_button_2  = 'No'
      default_button = '1'
    IMPORTING
      answer         = lv_answer.

  CHECK lv_answer = '1'.

  LOOP AT git_item ASSIGNING FIELD-SYMBOL(<ls_item>).
    READ TABLE lt_incomplete WITH KEY table_line = <ls_item>-docnum TRANSPORTING NO FIELDS.
    IF sy-subrc = 0.
      <ls_item>-sel = abap_true.
    ENDIF.
  ENDLOOP.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  SMART_CASE
*&---------------------------------------------------------------------*
* Some SAP standard messages (notably BAPI RETURN messages) come back
* fully in UPPERCASE, which reads as shouting in our screens/logs. If
* the given text has no lowercase letters at all, convert it to
* sentence case (first letter capitalized, rest lowercase). Text that
* already has any mixed/lower case is left exactly as-is - this is
* only a cosmetic fallback for the all-caps case, not a rewrite of
* normal text.
*---------------------------------------------------------------------*
FORM smart_case CHANGING pc_text TYPE any.

  DATA lv_text  TYPE string.
  DATA lv_upper TYPE string.

  lv_text = pc_text.
  CHECK lv_text CA 'abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ'.

  lv_upper = lv_text.
  TRANSLATE lv_upper TO UPPER CASE.
  CHECK lv_text = lv_upper. " already fully uppercase - nothing mixed/lower to preserve

  TRANSLATE lv_text TO LOWER CASE.
  DATA(lv_first) = lv_text(1).
  TRANSLATE lv_first TO UPPER CASE.
  lv_text = lv_first && lv_text+1.

  pc_text = lv_text.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  WRITE_LOG
*&---------------------------------------------------------------------*
FORM write_log USING pu_item        TYPE any
                      pu_action     TYPE char20
                      pu_status_from TYPE y0033fi_icm_status_n
                      pu_status_to   TYPE y0033fi_icm_status_n
                      pu_message     TYPE c.

* PU_ITEM accepts either TY_ITEM (used throughout Y0033FI_ICMS_F01) or
* Y0033FI_ICM_ITEM (the DB structure, used in Y0033FI_ICMS_F02) - both
* share the field names this form needs, so converting to a common
* local TY_ITEM work area here means callers never have to worry about
* which of the two types they are holding.
  DATA ls_item TYPE ty_item.
  MOVE-CORRESPONDING pu_item TO ls_item.

  DATA lv_lognr TYPE n LENGTH 6.
  PERFORM next_lognr USING ls_item-docnum ls_item-itmnum ls_item-seqnr
                   CHANGING lv_lognr.

  INSERT INTO y0033fi_icm_log VALUES @( VALUE #(
    docnum      = ls_item-docnum
    itmnum      = ls_item-itmnum
    seqnr       = ls_item-seqnr
    lognr       = lv_lognr
    bukrs       = ls_item-bukrs
    action      = pu_action
    status_from = pu_status_from
    status_to   = pu_status_to
    act_user    = sy-uname
    act_date    = sy-datum
    act_time    = sy-uzeit
    belnr       = ls_item-belnr_fi
    gjahr       = ls_item-gjahr_fi
    budat       = ls_item-budat_fi
    bldat       = ls_item-bldat_fi
    message     = pu_message ) ).

ENDFORM.

*&      Form  ENQUEUE_ITEM / DEQUEUE_ITEM
*&---------------------------------------------------------------------*
FORM enqueue_item USING pu_docnum TYPE j_1bnfdoc-docnum
                         pu_itmnum TYPE j_1bnflin-itmnum

*&---------------------------------------------------------------------*
*&      Form  SAVE_CANDIDATES
*&---------------------------------------------------------------------*
* Idempotent insert: writes the selected rows to Y0033FI_ICM_ITEM as
* STATUS = CANDIDATE, assigning the next SEQNR per item. If a row
* somehow already exists (race condition), the duplicate is reported
* without dumping.
*---------------------------------------------------------------------*
FORM save_candidates USING pu_id_exec TYPE char20.

  DATA lt_selected TYPE ty_it_item.
  LOOP AT git_item INTO DATA(ls_cand) WHERE sel = 'X' AND status = gc_status-ready_to_save.
    APPEND ls_cand TO lt_selected.
  ENDLOOP.
  IF lt_selected IS INITIAL.
    MESSAGE e002(y0033icms).
    RETURN.
  ENDIF.

  DATA lv_saved TYPE i.
  DATA lv_skip  TYPE i.

  LOOP AT lt_selected INTO DATA(ls_sel).
    DATA lv_subrc TYPE sy-subrc.
    PERFORM enqueue_item USING ls_sel-docnum ls_sel-itmnum 0 CHANGING lv_subrc.
    IF lv_subrc <> 0.
      lv_skip = lv_skip + 1.
      CONTINUE.
    ENDIF.

    " Final safety check: protects against a race with another user/
    " session saving the same item between search and this click
    " (FILTER_ACTIVE_CYCLE already removes items with an active cycle
    " from the search results, but that check ran moments earlier).
    " REVERSED and REJECTED are both "closed" outcomes - same reasoning
    " as FILTER_ACTIVE_CYCLE, which already let this item back into the
    " search results; this second check (done right before INSERT, to
    " catch a race since FILTER_ACTIVE_CYCLE ran moments earlier) must
    " agree with it, or a REJECTED item would pass the first check but
    " still get silently skipped here.
    SELECT COUNT(*) FROM y0033fi_icm_item
      INTO @DATA(lv_active_count)
      WHERE docnum = @ls_sel-docnum
        AND itmnum = @ls_sel-itmnum
        AND status <> @gc_status-reversed
        AND status <> @gc_status-rejected
        AND status <> @gc_status-cancelled_pre_post.
    IF lv_active_count > 0.
      lv_skip = lv_skip + 1.
      PERFORM dequeue_item USING ls_sel-docnum ls_sel-itmnum 0.
      CONTINUE.
    ENDIF.

    DATA lv_seqnr TYPE n LENGTH 3.
    PERFORM next_seqnr USING ls_sel-docnum ls_sel-itmnum CHANGING lv_seqnr.
    ls_sel-seqnr    = lv_seqnr.
    ls_sel-status   = gc_status-candidate.
    ls_sel-cre_user = sy-uname.
    ls_sel-cre_date = sy-datum.
    ls_sel-cre_time = sy-uzeit.
    ls_sel-id_exec  = pu_id_exec.

    INSERT y0033fi_icm_item FROM @( CORRESPONDING y0033fi_icm_item( ls_sel ) ).
    IF sy-subrc = 0.
      PERFORM write_log USING ls_sel gc_action-candidate_saved '000' gc_status-candidate
                               'Candidate saved by user'.
      " link this SEQNR to the eDoc tracking row, if we have a GUID
      IF ls_sel-edoc_guid IS NOT INITIAL.
        UPDATE y0033fi_icm_edoc SET seqnr = ls_sel-seqnr
          WHERE docnum = ls_sel-docnum AND edoc_guid = ls_sel-edoc_guid.
      ENDIF.
      lv_saved = lv_saved + 1.
    ELSE.
      lv_skip = lv_skip + 1.
    ENDIF.

    PERFORM dequeue_item USING ls_sel-docnum ls_sel-itmnum lv_seqnr.
  ENDLOOP.

  COMMIT WORK AND WAIT.
  MESSAGE s010(y0033icms) WITH lv_saved lv_skip.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  DELETE_CANDIDATES
*&---------------------------------------------------------------------*
* Lets the user remove a candidate saved by mistake, as long as it is
* still STATUS = CANDIDATE (not yet approved - once approved, the
* only way back is the normal reversal flow, which has its own audit
* trail). Deleting fully undoes the mistake: the row disappears from
* Y0033FI_ICM_ITEM, and the linked Y0033FI_ICM_EDOC row is released
* (SEQNR reset to 0) so the eDocument is free to be picked up again by
* a future search. The log entry from CANDIDATE_SAVED stays untouched
* - deletion is itself logged as a new action, not a rewrite of
* history.
*---------------------------------------------------------------------*
FORM delete_candidates.

  DATA lt_selected TYPE ty_it_item.
  LOOP AT git_item INTO DATA(ls_cand) WHERE sel = 'X' AND status = gc_status-candidate.
    APPEND ls_cand TO lt_selected.
  ENDLOOP.
  IF lt_selected IS INITIAL.
    MESSAGE e013(y0033icms).
    RETURN.
  ENDIF.

  DATA lv_deleted TYPE i.

  LOOP AT lt_selected INTO DATA(ls_sel).
    DATA lv_subrc TYPE sy-subrc.
    PERFORM enqueue_item USING ls_sel-docnum ls_sel-itmnum ls_sel-seqnr CHANGING lv_subrc.
    IF lv_subrc <> 0.
      CONTINUE.
    ENDIF.

    " STATUS = CANDIDATE in the WHERE guards against a stale grid: if
    " another session already moved this item on (e.g. approved it)
    " since this screen last refreshed, SY-SUBRC comes back <> 0 below
    " and nothing is deleted/logged, instead of blindly deleting
    " whatever the key still points to.
    DELETE FROM y0033fi_icm_item
      WHERE docnum = @ls_sel-docnum AND itmnum = @ls_sel-itmnum AND seqnr = @ls_sel-seqnr
        AND status = @gc_status-candidate.
    IF sy-subrc = 0.
      PERFORM write_log USING ls_sel gc_action-candidate_deleted gc_status-candidate '000'
                               'Candidate deleted by user'.
      IF ls_sel-edoc_guid IS NOT INITIAL.
        UPDATE y0033fi_icm_edoc SET seqnr = 0
          WHERE docnum = ls_sel-docnum AND edoc_guid = ls_sel-edoc_guid.
      ENDIF.
      lv_deleted = lv_deleted + 1.
    ENDIF.

    PERFORM dequeue_item USING ls_sel-docnum ls_sel-itmnum ls_sel-seqnr.
  ENDLOOP.

  COMMIT WORK AND WAIT.
  MESSAGE s014(y0033icms) WITH lv_deleted.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  REJECT_CANDIDATES
*&---------------------------------------------------------------------*
* Lets the user reject a candidate they no longer want to proceed
* with, as long as it's still STATUS = CANDIDATE (not yet approved).
* Unlike DELETE_CANDIDATES, the row stays in Y0033FI_ICM_ITEM (STATUS
* = REJECTED) instead of being removed, so it's still visible in
* "View My Candidates" for audit, not only in Y0033FI_ICM_LOG. Same as
* a deleted candidate, a rejected one does not permanently block the
* same nota/item from becoming a fresh candidate again in a future
* search (see FILTER_ACTIVE_CYCLE).
*---------------------------------------------------------------------*
FORM reject_candidates.

  DATA lt_selected TYPE ty_it_item.
  LOOP AT git_item INTO DATA(ls_cand) WHERE sel = 'X' AND status = gc_status-candidate.
    APPEND ls_cand TO lt_selected.
  ENDLOOP.
  IF lt_selected IS INITIAL.
    MESSAGE e020(y0033icms).
    RETURN.
  ENDIF.

  DATA lv_rejected TYPE i.

  LOOP AT lt_selected INTO DATA(ls_sel).
    DATA lv_subrc TYPE sy-subrc.
    PERFORM enqueue_item USING ls_sel-docnum ls_sel-itmnum ls_sel-seqnr CHANGING lv_subrc.
    IF lv_subrc <> 0.
      CONTINUE.
    ENDIF.

    " STATUS = CANDIDATE in the WHERE guards against a stale grid -
    " same reasoning as DELETE_CANDIDATES/APPROVE_CANDIDATES.
    UPDATE y0033fi_icm_item SET status = @gc_status-rejected
      WHERE docnum = @ls_sel-docnum AND itmnum = @ls_sel-itmnum AND seqnr = @ls_sel-seqnr
        AND status = @gc_status-candidate.
    IF sy-subrc = 0.
      PERFORM write_log USING ls_sel gc_action-candidate_rejected gc_status-candidate gc_status-rejected
                               'Rejected by user'.
      IF ls_sel-edoc_guid IS NOT INITIAL.
        UPDATE y0033fi_icm_edoc SET seqnr = 0
          WHERE docnum = ls_sel-docnum AND edoc_guid = ls_sel-edoc_guid.
      ENDIF.
      lv_rejected = lv_rejected + 1.
    ENDIF.

    PERFORM dequeue_item USING ls_sel-docnum ls_sel-itmnum ls_sel-seqnr.
  ENDLOOP.

  COMMIT WORK AND WAIT.
  MESSAGE s021(y0033icms) WITH lv_rejected.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  SHOW_LOG_POPUP
*&---------------------------------------------------------------------*
* Shows the full Y0033FI_ICM_LOG history (every SEQNR, every action)
* for the single selected item, in a read-only popup - no dedicated
* screen/status needed, CL_SALV_TABLE builds the popup entirely from
* code.
*---------------------------------------------------------------------*
FORM show_log_popup.

  DATA lt_selected TYPE ty_it_item.
  LOOP AT git_item INTO DATA(ls_cand) WHERE sel = 'X'.
    APPEND ls_cand TO lt_selected.
  ENDLOOP.

  IF lines( lt_selected ) <> 1.
    MESSAGE e015(y0033icms).
    RETURN.
  ENDIF.

  READ TABLE lt_selected INTO DATA(ls_sel) INDEX 1.

  SELECT * FROM y0033fi_icm_log
    INTO TABLE @DATA(lt_log)
    WHERE docnum = @ls_sel-docnum
      AND itmnum = @ls_sel-itmnum
    ORDER BY seqnr, lognr.

  IF lt_log IS INITIAL.
    MESSAGE s016(y0033icms).
    RETURN.
  ENDIF.

* Display-only projection of Y0033FI_ICM_LOG: adds the "<code> -
* <description>" text for STATUS_FROM/STATUS_TO (see
* STATUS_CODE_TO_DESCR) and picks/orders exactly the columns wanted,
* instead of showing every raw field of the log table. GT_LOG_DISP
* (TY_LOG_DISP, Y0033FI_ICMS_TOP) is global, not a local table here -
* see CLASS LCL_LOG_EVENTS for why (it needs to read the row back by

      seqnr    = ls_log-seqnr

      bukrs    = ls_log-bukrs
      belnr    = ls_log-belnr
      gjahr    = ls_log-gjahr
      message  = ls_log-message
      act_user = ls_log-act_user
      act_date = ls_log-act_date
      act_time = ls_log-act_time ).

    PERFORM status_code_to_descr USING ls_log-status_to   CHANGING ls_disp-status_to.
    APPEND ls_disp TO gt_log_disp.
  ENDLOOP.

  TRY.
      cl_salv_table=>factory(
        IMPORTING r_salv_table = DATA(lo_salv)
        CHANGING  t_table      = gt_log_disp ).

      lo_salv->get_columns( )->set_optimize( abap_true ).

      lo_columns->get_column( 'LOGNR' )->set_medium_text( 'Log' ).
      lo_columns->get_column( 'STATUS_FROM' )->set_medium_text( 'Status From' ).
      lo_columns->get_column( 'STATUS_TO' )->set_medium_text( 'Status To' ).
      lo_columns->get_column( 'BUKRS' )->set_technical( abap_true ).  " only needed for the FB03 call, see LCL_LOG_EVENTS
      " BELNR is clickable (hotspot) - opens FB03. See LCL_LOG_EVENTS.
      " SET_CELL_TYPE only exists on CL_SALV_COLUMN_TABLE, not on the

      DATA(lo_col_belnr) = CAST cl_salv_column_table( lo_columns->get_column( 'BELNR' ) ).

      lo_col_belnr->set_cell_type( if_salv_c_cell_type=>hotspot ).
      lo_columns->get_column( 'GJAHR' )->set_medium_text( 'Year' ).
      lo_columns->get_column( 'MESSAGE' )->set_medium_text( 'Log Message' ).
      lo_columns->get_column( 'ACT_USER' )->set_medium_text( 'User Name' ).

      SET HANDLER lcl_log_events=>on_link_click FOR lo_salv->get_event( ).

*&      Form  APPROVE_CANDIDATES

FORM approve_candidates.

*&---------------------------------------------------------------------*
*&      Form  REQUEST_REVERSAL
*&---------------------------------------------------------------------*
* Moves POSTED or CANCEL_DETECTED items to REVERSAL_REQUESTED.
* Callable by the user program or the admin program - the actual
* reversal posting only happens in Y0033FI_ICMS_F02 (admin-only), see
* FORM EXECUTE_REVERSAL there.
*---------------------------------------------------------------------*
FORM request_reversal.

  DATA lt_selected TYPE ty_it_item.
  LOOP AT git_item INTO DATA(ls_cand) WHERE sel = 'X'
                                         AND ( status = gc_status-posted
                                            OR status = gc_status-cancel_detected ).
    APPEND ls_cand TO lt_selected.
  ENDLOOP.
  IF lt_selected IS INITIAL.
    MESSAGE e005(y0033icms).
    RETURN.
  ENDIF.

  LOOP AT lt_selected INTO DATA(ls_sel).
    DATA lv_subrc TYPE sy-subrc.
    PERFORM enqueue_item USING ls_sel-docnum ls_sel-itmnum ls_sel-seqnr CHANGING lv_subrc.
    IF lv_subrc <> 0.
      CONTINUE.
    ENDIF.

    DATA(lv_trigger) = COND char20( WHEN ls_sel-status = gc_status-cancel_detected
                                     THEN gc_trigger-nf_canceled
                                     ELSE gc_trigger-manual ).

    " STATUS = LS_SEL-STATUS (the exact source status this screen last
    " saw - POSTED or CANCEL_DETECTED) guards against a stale grid: if
    " another session already moved this item on since then, SY-SUBRC
    " comes back <> 0 below and nothing is changed/logged. Matching the
    " exact remembered status (not just "still one of the two valid
    " ones") also protects LV_TRIGGER above, which was picked from that
    " same snapshot - if the real status flipped between POSTED and
    " CANCEL_DETECTED in the meantime, a future refresh will record the
    " correct trigger instead of a stale/wrong one.
    UPDATE y0033fi_icm_item SET status        = @gc_status-reversal_requested,
                                reversal_trigger  = @lv_trigger,
                                reversal_req_user = @sy-uname,
                                reversal_req_date = @sy-datum,
                                reversal_req_time = @sy-uzeit
      WHERE docnum = @ls_sel-docnum AND itmnum = @ls_sel-itmnum AND seqnr = @ls_sel-seqnr
        AND status = @ls_sel-status.

    IF sy-subrc = 0.
      DATA lv_msg_rev TYPE char200.
      lv_msg_rev = |Reversal requested (trigger { lv_trigger })|.
      PERFORM write_log USING ls_sel gc_action-reversal_requested ls_sel-status gc_status-reversal_requested
                               lv_msg_rev.
    ENDIF.

    PERFORM dequeue_item USING ls_sel-docnum ls_sel-itmnum ls_sel-seqnr.
  ENDLOOP.

  COMMIT WORK AND WAIT.
  MESSAGE s006(y0033icms).

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  CHECK_NF_CANCELLATION
*&---------------------------------------------------------------------*
* Re-reads J_1BNFDOC-CANCEL for every item currently POSTED. When the
* nota fiscal is found cancelled, moves the item to CANCEL_DETECTED.
* Also runs FORM SYNC_EDOC_TRACKING right after, per design decision
* (both checks share the same trigger - button or job).
*---------------------------------------------------------------------*
FORM check_nf_cancellation.

  SELECT docnum, itmnum, seqnr, belnr_fi, gjahr_fi
    FROM y0033fi_icm_item
    INTO TABLE @DATA(lt_posted)
    WHERE status = @gc_status-posted.

  " Online (screen 200 "Check Cancellations" button): only check what
  " the admin actually marked with SEL - same reasoning as
  " POST_RELEASED_ITEMS/EXECUTE_REVERSAL (Y0033FI_ICMS_F02). The
  " background job has no GIT_ITEM/screen at all and must keep
  " checking every POSTED item regardless, so this only applies
  " interactively.
  IF sy-batch = abap_false.
    LOOP AT lt_posted INTO DATA(ls_check).
      READ TABLE git_item WITH KEY docnum = ls_check-docnum
                                    itmnum = ls_check-itmnum
                                    seqnr  = ls_check-seqnr
        INTO DATA(ls_git_check).
      IF sy-subrc <> 0 OR ls_git_check-sel <> abap_true.
        DELETE lt_posted.
      ENDIF.
    ENDLOOP.
  ENDIF.

  DATA lv_flagged TYPE i.

  LOOP AT lt_posted INTO DATA(ls_posted).
    SELECT SINGLE cancel FROM j_1bnfdoc INTO @DATA(lv_cancel)
      WHERE docnum = @ls_posted-docnum.
    CHECK sy-subrc = 0 AND lv_cancel = abap_true.

    DATA lv_subrc TYPE sy-subrc.
    PERFORM enqueue_item USING ls_posted-docnum ls_posted-itmnum ls_posted-seqnr CHANGING lv_subrc.
    IF lv_subrc <> 0.
      CONTINUE.
    ENDIF.

    UPDATE y0033fi_icm_item SET status         = @gc_status-cancel_detected,
                                canc_det_date  = @sy-datum,
                                canc_det_time  = @sy-uzeit,
                                canc_det_user  = @sy-uname
      WHERE docnum = @ls_posted-docnum AND itmnum = @ls_posted-itmnum AND seqnr = @ls_posted-seqnr.

    IF sy-subrc = 0.
      DATA(ls_log_item) = VALUE ty_item( docnum = ls_posted-docnum
                                          itmnum = ls_posted-itmnum
                                          seqnr  = ls_posted-seqnr
                                          belnr_fi = ls_posted-belnr_fi
                                          gjahr_fi = ls_posted-gjahr_fi ).
      PERFORM write_log USING ls_log_item gc_action-cancel_detected gc_status-posted gc_status-cancel_detected
                               'Nota fiscal cancellation detected after posting'.
      lv_flagged = lv_flagged + 1.
    ENDIF.

    PERFORM dequeue_item USING ls_posted-docnum ls_posted-itmnum ls_posted-seqnr.
  ENDLOOP.

  IF lv_flagged > 0.
    COMMIT WORK AND WAIT.
  ENDIF.

  PERFORM sync_edoc_tracking.

  MESSAGE s011(y0033icms) WITH lv_flagged.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  REFRESH_FROM_DB
*&---------------------------------------------------------------------*
* Re-reads the persisted rows for the given selection so the ALV shows
* live STATUS/BELNR_FI/etc., and fills EDOC_GUID with the LATEST known
* eDocument for each nota fiscal (not necessarily the one originally
* used - see FORM GET_LATEST_EDOC_GUID and the design discussion).
*---------------------------------------------------------------------*
FORM refresh_from_db USING pu_bukrs TYPE bukrs.

  DATA lt_db TYPE STANDARD TABLE OF y0033fi_icm_item WITH DEFAULT KEY.

  DATA(lt_nfenum) = s_nfenum[].
  PERFORM pad_nfenum_range CHANGING lt_nfenum.

  " ACCESSKEY no longer lives on Y0033FI_ICM_ITEM (moved to
  " Y0033FI_ICM_EDOC, its natural 1:1 owner) - resolve S_ACCKEY into a
  " GUID range first, then filter ITEM by EDOC_GUID. An empty range
  " table imposes no restriction, matching the "no filter entered" case;
  " a non-empty S_ACCKEY that matches zero eDocuments must return zero
  " items too, so that case is handled explicitly below instead of
  " falling through to "no restriction".
  TYPES ty_r_guid TYPE RANGE OF char32.
  DATA lr_guid_acckey TYPE ty_r_guid.
  IF s_acckey[] IS NOT INITIAL.
    SELECT edoc_guid FROM y0033fi_icm_edoc
      INTO TABLE @DATA(lt_guid_acckey)
      WHERE accesskey IN @s_acckey.
    IF lt_guid_acckey IS INITIAL.
      CLEAR git_item.
      RETURN.
    ENDIF.
    lr_guid_acckey = VALUE #( FOR ls_guid IN lt_guid_acckey
                               ( sign = 'I' option = 'EQ' low = ls_guid ) ).
  ENDIF.

  " Action Date filter (S_ACTDAT + P_ASAV/P_AAPR/P_AREJ/P_APST) - lets
  " the user find items by when a lifecycle transition actually
  " happened, from Y0033FI_ICM_LOG, instead of relying on ITEM-level
  " date fields that either don't exist (REJECTED) or aren't reliable
  " for this purpose (BUDAT_FI can be backdated, or forced to today by
  " the period-closed retry in POST_RELEASED_ITEMS). Same "resolve to a
  " key list first" pattern as S_ACCKEY above: an empty S_ACTDAT range
  " imposes no restriction; a non-empty one that matches zero LOG rows
  " (or has every checkbox unchecked) must return zero items.
  TYPES: BEGIN OF ty_log_key,
           docnum TYPE y0033fi_icm_log-docnum,
           itmnum TYPE y0033fi_icm_log-itmnum,
           seqnr  TYPE y0033fi_icm_log-seqnr,
         END OF ty_log_key.
  DATA lt_log_keys TYPE STANDARD TABLE OF ty_log_key WITH DEFAULT KEY.
  DATA lv_actdat_filter TYPE abap_bool VALUE abap_false.
  IF s_actdat[] IS NOT INITIAL.
    lv_actdat_filter = abap_true.
    DATA lr_action TYPE RANGE OF y0033fi_icm_log-action.
    IF p_asav = abap_true.
      APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_action-candidate_saved ) TO lr_action.
    ENDIF.
    IF p_aapr = abap_true.
      APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_action-approved ) TO lr_action.
      APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_action-auto_approved ) TO lr_action.
    ENDIF.
    IF p_arej = abap_true.
      APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_action-candidate_rejected ) TO lr_action.
    ENDIF.
    IF p_apst = abap_true.
      APPEND VALUE #( sign = 'I' option = 'EQ' low = gc_action-posted ) TO lr_action.
    ENDIF.
    IF lr_action IS INITIAL.
      CLEAR git_item.
      RETURN.
    ENDIF.
    SELECT docnum, itmnum, seqnr FROM y0033fi_icm_log
      INTO TABLE @lt_log_keys
      WHERE act_date IN @s_actdat
        AND action   IN @lr_action.
    IF lt_log_keys IS INITIAL.
      CLEAR git_item.
      RETURN.
    ENDIF.
    SORT lt_log_keys BY docnum itmnum seqnr.
    DELETE ADJACENT DUPLICATES FROM lt_log_keys COMPARING docnum itmnum seqnr.
  ENDIF.

  " DOCDAT is the nota fiscal date - filtered by S_DOCDAT, same as in
  " search mode. S_DATUM (eDocument creation date) is applied right
  " below, against EDOCUMENT, not against DOCDAT (it used to be
  " compared with DOCDAT here, so an eDocument's own CREATE_DATE
  " typed into S_DATUM never matched anything in view mode).
  SELECT * FROM y0033fi_icm_item
    INTO TABLE @lt_db
    WHERE bukrs      = @pu_bukrs
      AND docdat     IN @s_docdat
      AND nfenum     IN @lt_nfenum
      AND docnum     IN @s_docnum
      AND series     IN @s_series
      AND edoc_guid  IN @lr_guid_acckey
      AND budat_fi   IN @s_lcto.

  " S_DATUM = eDocument date, same meaning as in search mode: the
  " eDocument's CREATE_DATE or CHANGE_DATE falls in the range (see
  " SELECT_CANDIDATE_DOCUMENTS for why CHANGE_DATE counts too).
  "
  " An item matches when ANY eDocument known for its nota fiscal
  " matches - not only the one persisted on the item (EDOC_GUID, the
  " eDocument it was created from). The grid shows the LATEST known
  " eDocument of the nota (see GET_LATEST_EDOC_GUID below), which may
  " be a different one - checking only the persisted GUID made an item
  " disappear when the user filtered by the date of the eDocument they
  " were actually looking at on screen.
  "
  " Items with no eDocument at all (stock-transfer model, which saves
  " EDOC_GUID blank and may have no Y0033FI_ICM_EDOC link either) can't
  " match an eDocument date and are dropped - same as in search mode,
  " where that model returns nothing when S_DATUM is filled.
  IF s_datum[] IS NOT INITIAL AND lt_db IS NOT INITIAL.
    TYPES: BEGIN OF ty_edoc_link,
             edoc_guid TYPE edocument-edoc_guid,
             docnum    TYPE j_1bnfdoc-docnum,
           END OF ty_edoc_link.
    DATA lt_edoc_link TYPE STANDARD TABLE OF ty_edoc_link WITH DEFAULT KEY.

    " 1) eDocument persisted on each item
    LOOP AT lt_db INTO DATA(ls_db_guid) WHERE edoc_guid IS NOT INITIAL.
      APPEND VALUE #( edoc_guid = ls_db_guid-edoc_guid docnum = ls_db_guid-docnum ) TO lt_edoc_link.
    ENDLOOP.

    " 2) every other eDocument linked to the same nota fiscal
    TYPES: BEGIN OF ty_docnum_key,
             docnum TYPE j_1bnfdoc-docnum,
           END OF ty_docnum_key.
    DATA lt_docnum_key TYPE STANDARD TABLE OF ty_docnum_key WITH DEFAULT KEY.
    LOOP AT lt_db INTO ls_db_guid.
      APPEND VALUE #( docnum = ls_db_guid-docnum ) TO lt_docnum_key.
    ENDLOOP.
    SORT lt_docnum_key BY docnum.
    DELETE ADJACENT DUPLICATES FROM lt_docnum_key COMPARING docnum.

    SELECT edoc_guid, docnum FROM y0033fi_icm_edoc
      INTO TABLE @DATA(lt_edoc_linked)
      FOR ALL ENTRIES IN @lt_docnum_key
      WHERE docnum = @lt_docnum_key-docnum
        AND status <> @gc_edoc_status-link_error.
    LOOP AT lt_edoc_linked INTO DATA(ls_edoc_linked).
      APPEND VALUE #( edoc_guid = ls_edoc_linked-edoc_guid docnum = ls_edoc_linked-docnum ) TO lt_edoc_link.
    ENDLOOP.
    SORT lt_edoc_link BY edoc_guid docnum.
    DELETE ADJACENT DUPLICATES FROM lt_edoc_link COMPARING edoc_guid docnum.

    " 3) which of those eDocuments are in the S_DATUM range
    TYPES: BEGIN OF ty_edoc_key,
             edoc_guid TYPE edocument-edoc_guid,
           END OF ty_edoc_key.
    DATA lt_edoc_in_range TYPE STANDARD TABLE OF ty_edoc_key WITH DEFAULT KEY.
    IF lt_edoc_link IS NOT INITIAL.
      SELECT edoc_guid FROM edocument
        INTO TABLE @lt_edoc_in_range
        FOR ALL ENTRIES IN @lt_edoc_link
        WHERE edoc_guid = @lt_edoc_link-edoc_guid
          AND ( create_date IN @s_datum OR change_date IN @s_datum ).
      SORT lt_edoc_in_range BY edoc_guid.
    ENDIF.

    " 4) nota fiscal numbers with at least one eDocument in range
    DATA lt_docnum_in_range TYPE STANDARD TABLE OF j_1bnfdoc-docnum WITH DEFAULT KEY.
    LOOP AT lt_edoc_link INTO DATA(ls_edoc_link).
      READ TABLE lt_edoc_in_range TRANSPORTING NO FIELDS BINARY SEARCH
        WITH KEY edoc_guid = ls_edoc_link-edoc_guid.
      IF sy-subrc = 0.
        APPEND ls_edoc_link-docnum TO lt_docnum_in_range.
      ENDIF.
    ENDLOOP.
    SORT lt_docnum_in_range BY table_line.
    DELETE ADJACENT DUPLICATES FROM lt_docnum_in_range COMPARING table_line.

    LOOP AT lt_db INTO ls_db_guid.
      READ TABLE lt_docnum_in_range TRANSPORTING NO FIELDS BINARY SEARCH
        WITH KEY table_line = ls_db_guid-docnum.
      IF sy-subrc <> 0.
        DELETE lt_db.
      ENDIF.
    ENDLOOP.
  ENDIF.

  CLEAR git_item.
  LOOP AT lt_db INTO DATA(ls_db).
    CLEAR gwa_item.
    MOVE-CORRESPONDING ls_db TO gwa_item.
    APPEND gwa_item TO git_item.
  ENDLOOP.
  " MOVE-CORRESPONDING converts each field at runtime, which tolerates
  " small type/length differences between the DB structure and GWA_ITEM
  " (e.g. NFENUM) that "INTO CORRESPONDING FIELDS OF TABLE" rejected at
  " compile time.

  IF lv_actdat_filter = abap_true.
    LOOP AT git_item INTO gwa_item.
      READ TABLE lt_log_keys TRANSPORTING NO FIELDS BINARY SEARCH
        WITH KEY docnum = gwa_item-docnum
                 itmnum = gwa_item-itmnum
                 seqnr  = gwa_item-seqnr.
      IF sy-subrc <> 0.
        DELETE git_item.
      ENDIF.
    ENDLOOP.
  ENDIF.

* NICE TO HAVE: for transfer-flow items (SELECT_TRANSFER_CANDIDATES),
* EDOC_GUID is saved blank (that flow has no eDocument dependency) and
* only ever resolved here, in memory, for display - if the inbound
* eDocument for the same DOCNUM only shows up later (plausible, given
* the two flows run independently), the persisted Y0033FI_ICM_ITEM
* row never gets backfilled, only what's shown on screen. Low
* priority: EDOC_GUID was never this flow's identity/traceability key
* (DOCNUM+ITMNUM+SEQNR is), so this only matters if something outside
* this program's own screens reads EDOC_GUID directly off the table.
  LOOP AT git_item INTO gwa_item.
    DATA(lv_tabix) = sy-tabix.
    DATA lv_latest_guid TYPE char32.
    PERFORM get_latest_edoc_guid USING gwa_item-docnum CHANGING lv_latest_guid.
    IF lv_latest_guid IS NOT INITIAL.
      gwa_item-edoc_guid = lv_latest_guid. " display: latest known, may differ from the one used at posting time
      MODIFY git_item FROM gwa_item INDEX lv_tabix.
    ENDIF.
  ENDLOOP.

  " EDOC_CREATE_DATE (display only, never persisted) - creation date of
  " the eDocument actually shown in the EDOC_GUID column, read in bulk.
  TYPES: BEGIN OF ty_edoc_disp,
           edoc_guid TYPE edocument-edoc_guid,
         END OF ty_edoc_disp.
  DATA lt_edoc_disp TYPE STANDARD TABLE OF ty_edoc_disp WITH DEFAULT KEY.
  LOOP AT git_item INTO gwa_item WHERE edoc_guid IS NOT INITIAL.
    APPEND VALUE #( edoc_guid = gwa_item-edoc_guid ) TO lt_edoc_disp.
  ENDLOOP.
  SORT lt_edoc_disp BY edoc_guid.
  DELETE ADJACENT DUPLICATES FROM lt_edoc_disp COMPARING edoc_guid.
  IF lt_edoc_disp IS NOT INITIAL.
    SELECT edoc_guid, create_date FROM edocument
      INTO TABLE @DATA(lt_edoc_cdate)
      FOR ALL ENTRIES IN @lt_edoc_disp
      WHERE edoc_guid = @lt_edoc_disp-edoc_guid.
    SORT lt_edoc_cdate BY edoc_guid.
    LOOP AT git_item INTO gwa_item WHERE edoc_guid IS NOT INITIAL.
      DATA(lv_tabix_cd) = sy-tabix.
      READ TABLE lt_edoc_cdate INTO DATA(ls_edoc_cdate) BINARY SEARCH
        WITH KEY edoc_guid = gwa_item-edoc_guid.
      IF sy-subrc = 0.
        gwa_item-edoc_create_date = ls_edoc_cdate-create_date.
        MODIFY git_item FROM gwa_item INDEX lv_tabix_cd TRANSPORTING edoc_create_date.
      ENDIF.
    ENDLOOP.
  ENDIF.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  APPLY_STATUS_FILTER
*&---------------------------------------------------------------------*
* Keeps only the rows whose STATUS is checked on the filter
* checkboxes (PU_RANGE, built by GET_STATUS_FILTER_SEARCH/_VIEW).
* Unchecking every box is not a no-op - it means "show nothing", same
* as an empty range matching nothing.
*---------------------------------------------------------------------*
FORM apply_status_filter USING pu_range TYPE ty_r_status.

  DELETE git_item WHERE status NOT IN pu_range.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  BUILD_FIELDCAT
*&---------------------------------------------------------------------*
* PU_MODE is no longer used to vary the column set - admin and user
* cockpit now show the exact same columns. Kept as a parameter only
* so existing callers (PU_MODE = 'U'/'A') don't need to change.
*---------------------------------------------------------------------*
FORM build_fieldcat USING pu_mode TYPE c.
  DATA: ls_fcat TYPE lvc_s_fcat.

  DEFINE add_field.
    CLEAR ls_fcat.
    ls_fcat-fieldname = &1.
    ls_fcat-coltext   = &2.
    ls_fcat-outputlen = &3.
    APPEND ls_fcat TO gt_fcat.
  END-OF-DEFINITION.

  CLEAR gt_fcat.
  " SEL - real checkbox column, made clickable via CHECKBOX + EDIT,
  " same proven pattern as Y0033FI_ICM_LANE's grid on screen 300.
  " Requires IS_LAYOUT-EDIT = 'X' on the calling screen (see
  " SCR_100/SCR_200) - only this field actually behaves as editable,
  " since no other field below sets EDIT.
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'SEL'.
  ls_fcat-coltext   = 'Sel.'.
  ls_fcat-outputlen = 4.
  ls_fcat-checkbox  = abap_true.
  ls_fcat-edit      = abap_true.
  APPEND ls_fcat TO gt_fcat.

  " STATUS_ICON - traffic-light icon, right next to SEL so it's the
  " first thing seen (see BUILD_STATUS_ICONS).
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'STATUS_ICON'.
  ls_fcat-coltext   = 'Status'.
  ls_fcat-outputlen = 4.
  ls_fcat-icon      = abap_true.
  APPEND ls_fcat TO gt_fcat.

  " STATUS_DESCR - "<code> - <description>", right next to the icon
  " (see BUILD_STATUS_DESCR) so the user learns the numeric codes.
  add_field 'STATUS_DESCR' 'Status'            28.

  " Display order: NFe Date, NFe Number, Cycle, Item (also the sort/
  " grouping key - see BUILD_SORT_TABLE/BUILD_NOTA_COLOR), then
  " DocNum, Series.
  add_field 'DOCDAT'      'NFe Date'           10.
  add_field 'NFENUM'      'NFe Number'         12.
  add_field 'SEQNR'       'Cycle'               6.
  add_field 'ITMNUM'      'Item'                6.

  " DOCNUM is clickable (hotspot) - opens J1BNFE. See LCL_ALV_EVENTS.
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'DOCNUM'.
  ls_fcat-coltext   = 'DocNum'.
  ls_fcat-outputlen = 12.
  ls_fcat-hotspot   = abap_true.
  APPEND ls_fcat TO gt_fcat.
  add_field 'SERIES'      'Series'              4.

  " DOCNUM_ORIG/DOCNUM_DEST - origin/destination DOCNUM for this same
  " NFENUM+SERIES+BUKRS, resolved by whichever search model found the
  " candidate (see SELECT_CANDIDATE_DOCUMENTS/SELECT_TRANSFER_CANDIDATES).
  " Display only for now - NOT YET PERSISTED (Y0033FI_ICM_ITEM has no
  " matching DDIC fields yet), so these go blank again after a reload
  " from the DB (View/Admin modes) until that DDIC change is made.
  add_field 'DOCNUM_ORIG' 'DocNum Orig.'       12.
  add_field 'DOCNUM_DEST' 'DocNum Dest.'       12.

  " MATNR gets its own entry (not the plain macro) so the ALV applies
  " the material number conversion exit (leading zero handling, etc.)
  " via the reference table/field, instead of showing the raw value.
  CLEAR ls_fcat.
  ls_fcat-fieldname  = 'MATNR'.
  ls_fcat-coltext    = 'Material'.
  ls_fcat-outputlen  = 18.
  ls_fcat-ref_table  = 'MARA'.
  ls_fcat-ref_field  = 'MATNR'.
  APPEND ls_fcat TO gt_fcat.

  add_field 'CFOP'        'CFOP'                8.

  add_field 'ICMS_BASE'   'ICMS Base'          16.
  add_field 'ICMS_EXCBAS' 'Excluded Base'      16.
  add_field 'ICMS_OTHBAS' 'Other Base'         16.
  add_field 'ICMS_RATE'   'ICMS Rate'          10.
  add_field 'ICMS_VAL'    'ICMS on NF'         18.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'BENEFIT_PERCENT'.
  ls_fcat-coltext   = 'Benefit %'.
  ls_fcat-outputlen = 12.
  APPEND ls_fcat TO gt_fcat.

  CLEAR ls_fcat.
  ls_fcat-fieldname = 'CREDIT_AMOUNT'.
  ls_fcat-coltext   = 'ICMS Credit'.
  ls_fcat-outputlen = 14.
  APPEND ls_fcat TO gt_fcat.

  add_field 'WAERS'       'Cur.'                5.

  " EDOC_GUID is clickable (hotspot) - see LCL_ALV_EVENTS in the TOP
  " include, registered on the grid in each screen's PBO.
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'EDOC_GUID'.
  ls_fcat-coltext   = 'eDocument'.
  ls_fcat-outputlen = 20.
  ls_fcat-hotspot   = abap_true.
  APPEND ls_fcat TO gt_fcat.

  " Display only - not a Y0033FI_ICM_ITEM field, see EDOC_CREATE_DATE
  " in TY_ITEM (Y0033FI_ICMS_TOP).
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'EDOC_CREATE_DATE'.
  ls_fcat-coltext   = 'eDoc Created on'.
  ls_fcat-outputlen = 10.
  ls_fcat-datatype  = 'DATS'.
  APPEND ls_fcat TO gt_fcat.

  " A607 access-key fields (see DETERMINE_BENEFIT_PERCENTAGE) - shown
  " for traceability, so it's visible exactly which combination
  " (country/origin/destination/material origin) produced the matched
  " condition record and its validity window.
  add_field 'LAND1'      'Country'             4.
  add_field 'REGIO_ORIG' 'Ship-from UF'       12.
  add_field 'REGIO_DEST' 'Ship-to UF'         12.
  add_field 'MATORG'     'Mat. Origin'        10.
  add_field 'KSCHL'      'Cond. Type'         10.
  add_field 'KNUMH'      'Condition Rec.'     14.
  add_field 'DATAB'      'Valid From'         10.
  add_field 'DATBI'      'Valid To'           10.

  " Same columns for both screens now (admin and user cockpit share
  " this catalog regardless of PU_MODE) - all of these come from the
  " same TY_ITEM structure, so nothing extra needs to be read.
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'BELNR_FI'.
  ls_fcat-coltext   = 'Acc. Document'.
  ls_fcat-outputlen = 12.
  ls_fcat-hotspot   = abap_true.
  APPEND ls_fcat TO gt_fcat.

  add_field 'BUZEI_FI'    'Item'              6.
  add_field 'CRE_USER'    'Created by'       12.
  add_field 'CRE_DATE'    'Created on'       10.
  add_field 'CRE_TIME'    'Created at'       10.
  add_field 'APR_USER'    'Approved by'      12.
  add_field 'APR_DATE'    'Approved on'      10.
  add_field 'APR_TIME'    'Approved at'      10.
  add_field 'PST_USER'    'Posted by'        12.
  add_field 'PST_DATE'    'Posted on'        10.
  add_field 'PST_TIME'    'Posted at'        10.
  add_field 'REVERSAL_TRIGGER' 'Rev. trigger'    20.

  " REVERSAL_BELNR - the reversal accounting document (distinct from
  " BELNR_FI, the original posted document) - clickable the same way,
  " see WHEN 'REVERSAL_BELNR' in LCL_ALV_EVENTS (Y0033FI_ICMS_TOP).
  " Blank until EXECUTE_REVERSAL (Y0033FI_ICMS_F02) actually reverses
  " the item.
  CLEAR ls_fcat.
  ls_fcat-fieldname = 'REVERSAL_BELNR'.
  ls_fcat-coltext   = 'Reversal Doc.'.
  ls_fcat-outputlen = 12.
  ls_fcat-hotspot   = abap_true.
  APPEND ls_fcat TO gt_fcat.

  add_field 'MSG' 'Message / Pending' 60.

ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  BUILD_SORT_TABLE
*&---------------------------------------------------------------------*
* Default sort for the main item grid: NFe Date, NFe Number and Item,
* all ascending - this also groups every item of the same nota fiscal
* together, which BUILD_NOTA_COLOR relies on (it physically re-sorts
* GIT_ITEM the same way before banding, since GT_SORT here only
* affects the ALV's own display, not GIT_ITEM's underlying row order).
* The user can still click any column header to re-sort manually -
* this only sets the initial order.
*---------------------------------------------------------------------*
FORM build_sort_table.

  CLEAR gt_sort.

  APPEND VALUE #( spos = 1 fieldname = 'DOCDAT'  up = abap_true  down = space ) TO gt_sort.
  APPEND VALUE #( spos = 2 fieldname = 'NFENUM'  up = abap_true  down = space ) TO gt_sort.
  APPEND VALUE #( spos = 3 fieldname = 'SEQNR'   up = abap_true  down = space ) TO gt_sort.
  APPEND VALUE #( spos = 4 fieldname = 'ITMNUM'  up = abap_true  down = space ) TO gt_sort.

ENDFORM.
