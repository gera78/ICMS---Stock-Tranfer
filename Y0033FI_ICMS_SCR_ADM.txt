*&---------------------------------------------------------------------*
*& Include Y0033FI_ICMS_SCR_ADM
*&---------------------------------------------------------------------*
*& CR 16002 - Selection screen for Y0033FI_ICM_STOCK_TRANSFER_ADM.
*& Same fields whether the program runs interactively or in
*& background (SY-BATCH) - see START-OF-SELECTION in the main program.
*&
*& Admin now also has access to the user-style actions (search new
*& candidates / view+approve+request reversal), reusing screen 100
*& and Y0033FI_ICMS_SCR_100 - the mode radio button below decides
*& which screen the program opens.
*&
*& This include holds ONLY what is exclusive to the admin program:
*& P_MADM/P_MPARM/P_MLANE and the MAG1/MAG2 admin filter shortcuts.
*& Everything P_MNEW/P_MVIEW themselves need (P_BUKRS, the search/view
*& filters, the 11 status checkboxes, MVG1/MVG3/MVG2) is declared once
*& in Y0033FI_ICMS_SCR_USR (which the main program includes BEFORE
*& this one) and reused here as-is - see that include's own header
*& comment.
*&
*& P_MADM/P_MPARM/P_MLANE are their OWN separate RADIOBUTTON GROUP
*& (MODA), not part of Y0033FI_ICMS_SCR_USR's MOD group (P_MNEW/
*& P_MVIEW) - SAP requires every member of a group to be declared in
*& the same block, and MOD's block is already closed inside that
*& include. Two visible side effects: the mode choice renders as two
*& frames instead of one (Search/View in the shared frame, Admin
*& Review/Parameters/Corridors right below in an untitled one), and
*& keeping only one of the 5 radio buttons checked at a time is done
*& by hand (in FORM ADM_SCR_EVENT below), not by SAP automatically -
*& see the comment on B2B.
*&
*& This include does NOT declare its own INITIALIZATION/AT
*& SELECTION-SCREEN OUTPUT/AT SELECTION-SCREEN - each of those events
*& may only be coded ONCE per program, and Y0033FI_ICMS_SCR_USR
*& already owns all three (needed there for standalone use). Instead,
*& this include's reactive logic lives in plain FORMs (ADM_SCR_INIT/
*& ADM_SCR_OUTPUT/ADM_SCR_EVENT), which Y0033FI_ICMS_SCR_USR calls via
*& PERFORM (...) IF FOUND - a dynamic call that compiles fine even in
*& the plain user program, where these FORMs don't exist at all.
*&---------------------------------------------------------------------*

SELECTION-SCREEN BEGIN OF BLOCK b2b WITH FRAME.
* A SEPARATE RADIOBUTTON GROUP (MODA, not MOD) - SAP requires every
* member of a group to live in the SAME block, and MOD's block (B2)
* is already closed inside Y0033FI_ICMS_SCR_USR (needed there, since
* that include is also used standalone without these extra modes) -
* trying to add these three to MOD from here fails activation
* ("parameter of the radio button group already defined in block B2").
*
* Being a different group, SAP does NOT keep this mutually exclusive
* with P_MNEW/P_MVIEW automatically - FORM ADM_SCR_EVENT below clears
* one group's members whenever the other one changes, using MOD_CHG2
* (this group's own USER-COMMAND, on P_MADM) alongside
* Y0033FI_ICMS_SCR_USR's existing MOD_CHG.
PARAMETERS:
  p_madm  RADIOBUTTON GROUP moda DEFAULT 'X' USER-COMMAND mod_chg2,   " admin review (original behavior) - this program's own default, see FORM ADM_SCR_INIT
  p_mparm RADIOBUTTON GROUP moda,   " General Parameters (screen 400)
  p_mlane RADIOBUTTON GROUP moda.   " Maintain Corridors (screen 300)
SELECTION-SCREEN END OF BLOCK b2b.

SELECTION-SCREEN BEGIN OF BLOCK b3c WITH FRAME.
* Admin-only "master" checkboxes - group-toggle the SAME 11 status
* filter checkboxes Y0033FI_ICMS_SCR_USR declares (B3B there), for
* P_MADM instead of P_MVIEW. Own untitled frame, visually separate
* from B3B (declared and closed entirely in Y0033FI_ICMS_SCR_USR) - a
* block opened in one include cannot be reopened/extended from
* another. MODIF ID MA (not MV, which B3B's own masters use) so each
* mode's master checkboxes can be shown/hidden independently - see
* FORM ADM_SCR_OUTPUT below.
SELECTION-SCREEN BEGIN OF LINE.
PARAMETERS p_mag1 TYPE char1 AS CHECKBOX DEFAULT 'X' USER-COMMAND mag1 MODIF ID ma.
SELECTION-SCREEN COMMENT 4(60) c_mag1 MODIF ID ma.
SELECTION-SCREEN END OF LINE.
SELECTION-SCREEN BEGIN OF LINE.
PARAMETERS p_mag2 TYPE char1 AS CHECKBOX USER-COMMAND mag2 MODIF ID ma.
SELECTION-SCREEN COMMENT 4(60) c_mag2 MODIF ID ma.
SELECTION-SCREEN END OF LINE.
SELECTION-SCREEN END OF BLOCK b3c.

*&---------------------------------------------------------------------*
*&      Form  ADM_SCR_INIT
*&---------------------------------------------------------------------*
* Called from Y0033FI_ICMS_SCR_USR's INITIALIZATION via
* PERFORM ('ADM_SCR_INIT') IF FOUND - see this include's own header
* comment for why it can't just be this program's own INITIALIZATION.
*---------------------------------------------------------------------*
FORM adm_scr_init.
* This program's own default mode, overriding Y0033FI_ICMS_SCR_USR's
* own INITIALIZATION (P_MNEW), which already ran by this point (it
* calls this FORM at the very end of its own INITIALIZATION) -
* preserves this program's original behavior (admin review opens by
* default).
  p_mnew  = abap_false.
  p_mview = abap_false.
  p_madm  = abap_true.

  c_mag1 = 'Needs admin action (020, 025, 060)'.
  c_mag2 = 'Others (010, 015, 030, 040, 045, 050, 070, 990)'.

  PERFORM set_adm_status_defaults.
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  ADM_SCR_OUTPUT
*&---------------------------------------------------------------------*
* Called from Y0033FI_ICMS_SCR_USR's AT SELECTION-SCREEN OUTPUT via
* PERFORM ('ADM_SCR_OUTPUT') IF FOUND - see this include's own header
* comment.
*---------------------------------------------------------------------*
FORM adm_scr_output.
  LOOP AT SCREEN.
    IF screen-group1 = 'FV' AND p_madm = 'X'.
      screen-active = 1.  " admin review also uses the FV group (S_LCTO/S_ACTDAT + the 11 status checkboxes) - Y0033FI_ICMS_SCR_USR's own OUTPUT block only knows about P_MVIEW and already hid it based on that alone
      MODIFY SCREEN.
    ENDIF.
    IF screen-group1 = 'MA' AND p_madm <> 'X'.
      screen-active = 0.  " hide the "Admin" master checkboxes outside admin review mode
      MODIFY SCREEN.
    ENDIF.
  ENDLOOP.
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  ADM_SCR_EVENT
*&---------------------------------------------------------------------*
* Called from Y0033FI_ICMS_SCR_USR's AT SELECTION-SCREEN via
* PERFORM ('ADM_SCR_EVENT') IF FOUND - see this include's own header
* comment.
*---------------------------------------------------------------------*
FORM adm_scr_event.
* P_MNEW/P_MVIEW (group MOD, Y0033FI_ICMS_SCR_USR) and P_MADM/P_MPARM/
* P_MLANE (group MODA, B2B above) are two INDEPENDENT RADIOBUTTON
* GROUPs (see the comment on B2B for why) - SAP keeps each group
* mutually exclusive on its own, but does nothing to keep the two
* groups exclusive OF EACH OTHER, so without this, switching from one
* group to the other would leave both showing a checked radio at once.
* MOD_CHG2 is MODA's own USER-COMMAND (on P_MADM, same idea as
* Y0033FI_ICMS_SCR_USR's MOD_CHG on P_MNEW - fires for a click on any
* member of that member's group).
  CASE sy-ucomm.
    WHEN 'MOD_CHG'.
      " user switched within MOD (P_MNEW/P_MVIEW) - clear MODA.
      p_madm  = abap_false.
      p_mparm = abap_false.
      p_mlane = abap_false.
    WHEN 'MOD_CHG2'.
      " user switched within MODA (P_MADM/P_MPARM/P_MLANE) - clear MOD.
      p_mnew  = abap_false.
      p_mview = abap_false.
      " Y0033FI_ICMS_SCR_USR's own MOD_CHG handling doesn't run for
      " this UCOMM, so the P_MADM-specific reset is applied here
      " instead (no-ops for P_MPARM/P_MLANE, which have no status
      " filter of their own - see the FORM itself).
      PERFORM set_adm_status_defaults.
  ENDCASE.

* "Master" checkboxes (B3C) - group-toggle the real filter checkboxes
* when clicked. See the block comment above P_MAG1 for what each
* group covers. MVG1/MVG3/MVG2 are handled by Y0033FI_ICMS_SCR_USR's
* own AT SELECTION-SCREEN block, not here.
  CASE sy-ucomm.
    WHEN 'MAG1'.
      p_vap = p_mag1.  p_vpf = p_mag1.  p_vrr = p_mag1.
    WHEN 'MAG2'.
      p_vca = p_mag2.  p_vrj = p_mag2.  p_vpg = p_mag2.  p_vcd = p_mag2.
      p_vpo = p_mag2.  p_vrv = p_mag2.  p_ver = p_mag2.  p_vcb = p_mag2.
  ENDCASE.

* Keep both master checkboxes honest: recompute each from its actual
* children on EVERY round trip (not just when the master itself was
* clicked) - same reasoning as Y0033FI_ICMS_SCR_USR's own MVG1/MVG3/
* MVG2 recompute.
  p_mag1 = COND #( WHEN p_vap = abap_true AND p_vpf = abap_true AND p_vrr = abap_true
                    THEN abap_true ELSE abap_false ).
  p_mag2 = COND #( WHEN p_vca = abap_true AND p_vrj = abap_true AND p_vpg = abap_true
                         AND p_vcd = abap_true AND p_vpo = abap_true AND p_vrv = abap_true
                         AND p_ver = abap_true AND p_vcb = abap_true
                    THEN abap_true ELSE abap_false ).
ENDFORM.

*&---------------------------------------------------------------------*
*&      Form  SET_ADM_STATUS_DEFAULTS
*&---------------------------------------------------------------------*
* The P_MADM-specific half of the status filter reset.
* SET_STATUS_FILTER_DEFAULTS (Y0033FI_ICMS_SCR_USR) already handles
* P_MNEW/P_MVIEW and is called unconditionally from both programs'
* INITIALIZATION/MOD_CHG handling - this FORM only adds what that one
* cannot know about (P_MADM doesn't exist in the plain user program),
* called right after it (from ADM_SCR_INIT/ADM_SCR_EVENT above).
*---------------------------------------------------------------------*
FORM set_adm_status_defaults.
  IF p_madm = 'X'.
    p_vap = abap_true.   p_vpf = abap_true.   p_vrr = abap_true.  " needs admin action (020, 025, 060)
    p_vca = abap_false.  p_vrj = abap_false.  p_vpg = abap_false.
    p_vcd = abap_false.  p_vpo = abap_false.  p_vrv = abap_false.  p_ver = abap_false.
    p_vcb = abap_false.  " others (045 included - no admin action exists for Cancelled Before Posting)
  ENDIF.
ENDFORM.
