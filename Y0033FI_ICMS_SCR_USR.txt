  SELECT-OPTIONS:
* Date filters - each one means the same thing in every mode:
*   S_DATUM  = eDocument date: EDOCUMENT-CREATE_DATE OR CHANGE_DATE in
*              range (in view mode: of any eDocument of the nota). Strict:
*              items with no eDocument (stock-transfer search model)
*              never match it, so none of them come back when it's filled.
*   S_DOCDAT = nota fiscal date (J_1BNFDOC-DOCDAT / ITEM-DOCDAT).
*   S_AUTDAT = NF-e authorization date at SEFAZ (J_1BNFE_ACTIVE-AUTHDATE)
*              - stock-transfer model, search only. Authorization can
*              come hours after the nota's own date, so a daily job
*              should use this one (yesterday..today), not S_DOCDAT.
*   S_LCTO   = posting date of the accounting document (BUDAT_FI) -
*              view mode only.
*   S_ACTDAT = date an action happened (Y0033FI_ICM_LOG) - view mode only.
    s_datum  FOR sy-datum MODIF ID ed,            " eDocument date (created or changed) - eDocument model only, see MODIF ID ED below
    s_nfenum FOR j_1bnfdoc-nfenum,                " NFe number - zero-padded automatically, see SELECT_CANDIDATE_DOCUMENTS
    s_docnum FOR j_1bnfdoc-docnum,                " internal nota fiscal document number
    s_series FOR j_1bnfdoc-series,                " NFe series
    s_docdat FOR j_1bnfdoc-docdat,                " nota fiscal date - every mode (search: J_1BNFDOC-DOCDAT, view: ITEM-DOCDAT, see REFRESH_FROM_DB)
    s_autdat FOR sy-datum MODIF ID fs,            " NF-e authorization date (J_1BNFE_ACTIVE-AUTHDATE) - transfer model, search only
    s_acckey FOR y0033fi_icm_edoc-accesskey MODIF ID ed, " eDocument model only (MODIF ID ED) - NF-e access key (44 digits) - typed against Y0033FI_ICM_EDOC-ACCESSKEY (CHAR44), not the source table directly: EDOBRINCOMING-ACCESSKEY is TYPE STRING, which selection-screen fields can't use
* S_LCTO only applies in view mode - nothing is posted yet in search
* mode, so it is hidden there (same MODIF ID FV as the status filter).
    s_lcto   FOR sy-datum MODIF ID fv,
* TODO (Q5/Q8): reference date for selection still pending - uses
* nota fiscal issue date for now.
* Action Date - view mode only (same MODIF ID FV). Distinct from
* S_DATUM (eDocument creation date) and S_LCTO (BUDAT_FI, the posting
* accounting date, which is not reliable for "posted on date X": it
* can be backdated and gets forced to today by the period-closed retry
* in POST_RELEASED_ITEMS). Filters by when a lifecycle transition
* actually happened, per Y0033FI_ICM_LOG-ACT_DATE - the only place
* REJECTED has a date at all, since Y0033FI_ICM_ITEM has no field for it.
    s_actdat FOR sy-datum MODIF ID fv.

AT SELECTION-SCREEN OUTPUT.
  LOOP AT SCREEN.
    IF screen-group1 = 'FS' AND p_mnew <> 'X'.
      screen-active = 0.  " hide entirely - only applies when searching new candidates
      MODIFY SCREEN.
    ENDIF.
    IF screen-group1 = 'ED' AND gc_enable_search_edoc = abap_false.
      screen-active = 0.  " eDocument filters (S_DATUM/S_ACCKEY) - only with the eDocument model (GC_ENABLE_SEARCH_EDOC, Y0033FI_ICMS_TOP)
      MODIFY SCREEN.
    ENDIF.
    IF screen-group1 = 'FV' AND p_mview <> 'X'.
      screen-active = 0.  " hide entirely - only applies to view mode
      MODIFY SCREEN.
    ENDIF.
  ENDLOOP.

AT SELECTION-SCREEN.
* ONLI = the user pressed Execute (F8), not just clicked a radio
* button/checkbox - only THEN is P_BUKRS actually required (and its
* authorization worth checking).
  PERFORM clear_edoc_filters USING gc_enable_search_edoc.  " hidden eDocument filters never restrict (or count as a filter) - see CLEAR_EDOC_FILTERS
  IF sy-ucomm = 'ONLI'.
    IF p_bukrs IS INITIAL.
      MESSAGE 'Enter a Company Code' TYPE 'E'.
    ENDIF.
    PERFORM check_bukrs_authority USING p_bukrs.
    IF p_mnew = 'X'.
      PERFORM check_search_filters.
    ENDIF.
  ENDIF.

* Mode just switched (MOD_CHG fires for any change within the P_MNEW/
* P_MVIEW radio group, not only when P_MNEW itself is clicked) - reset
* each mode's own status filter to its defined default, exactly as if
* the screen were opened fresh in that mode. This intentionally
* overwrites any manual per-checkbox tweak made before switching away.
  IF sy-ucomm = 'MOD_CHG'.
    IF p_mnew = 'X'.
      p_sre = abap_true.  p_snc = abap_false.  p_ser = abap_false.
    ELSEIF p_mview = 'X'.
      p_vca = abap_true.   p_vcd = abap_true.                    " needs my action (010, 050)
      p_vpo = abap_false.                                        " reversal (040) - off by default
      p_vrj = abap_false.  p_vap = abap_false.  p_vpf = abap_false.  p_vcb = abap_false.
      p_vpg = abap_false.  p_vrr = abap_false.  p_vrv = abap_false.  p_ver = abap_false. " others
    ENDIF.
  ENDIF.

* "Master" checkboxes (B3B) - group-toggle the real filter checkboxes
* when clicked. See the block comment above P_MVG1 for what each
* group covers.
  CASE sy-ucomm.
    WHEN 'MVG1'.
      p_vca = p_mvg1.  p_vcd = p_mvg1.
    WHEN 'MVG3'.
      p_vpo = p_mvg3.
    WHEN 'MVG2'.
      p_vrj = p_mvg2.  p_vap = p_mvg2.  p_vpf = p_mvg2.  p_vcb = p_mvg2.  p_vpg = p_mvg2.
      p_vrr = p_mvg2.  p_vrv = p_mvg2.  p_ver = p_mvg2.
  ENDCASE.

* Keep the master checkboxes honest: recompute them from their actual
* children on EVERY round trip (not just when the master itself was
* clicked) - otherwise switching between Search/View (or any other
* trip to the server, e.g. pressing Execute) kept showing whichever
* value the master had last, even after a child was unchecked
* individually, instead of tracking its children's real combined state.
  p_mvg1 = COND #( WHEN p_vca = abap_true AND p_vcd = abap_true
                    THEN abap_true ELSE abap_false ).
  p_mvg3 = COND #( WHEN p_vpo = abap_true THEN abap_true ELSE abap_false ).
  p_mvg2 = COND #( WHEN p_vrj = abap_true AND p_vap = abap_true AND p_vpf = abap_true AND p_vcb = abap_true
                         AND p_vpg = abap_true AND p_vrr = abap_true AND p_vrv = abap_true
                         AND p_ver = abap_true
                    THEN abap_true ELSE abap_false ).
